# C36-C outside-ui: development notes

- Unit tests: `apps/web/test/access-outside-ui.test.ts` (static renders and a mocked fetch; includes the import-graph guard for the public page). C35's `access-ui.test.ts` is unchanged and green.
- Browser spec: `apps/web/e2e/access-outside.spec.ts` (`LANDFLOW_INTEGRATION=browser pnpm test:browser -- access-outside.spec.ts`). It starts its own scratch host with a loopback SMTP sink (for the sign-in link) and `fakeGoogleOidc`, so it needs no Mailpit. It skips, saying why, while `/request-access/api/config` answers 404 (C36-A/B not merged). It was written against plan.md's route table and has not run against the real routes.
- Assumptions made where plan.md gives no shape (the integrator should check them against A and B): `GET /request-access/api/entries|requests|grants` answer `{ items }` (a bare array is accepted); an open entry carries `id, name, description?, durations, target.label | targetLabel, needsGithub | githubRequired, system?`; `GET account` answers `{ github? }`; `GET /api/access/outside` answers `{ enabled, domains, google: { enabled, credentialId? }, link? }` and PUT takes the same without `link`; `GET /api/access/outside/requesters` answers `{ items: [{ id, email, verifiedBy, createdAt, lastSeenAt?, openRequests, liveGrants, blocked }] }`; the entry view carries `outsideMayAsk` and PATCH takes it; requests and grants of outsiders carry `requester|holder: { kind: 'outside', email, verifiedBy }`.
- `/request-access` must be in `PUBLIC_PAGES` (`lib/shared/auth-paths.ts`, C36-A's file): without it the root layout sends the page to /login.
- The page calls `/api/auth/me` once, quietly, to show the "You have a Landflow account" line; it answers 401 to outsiders (one console line).
