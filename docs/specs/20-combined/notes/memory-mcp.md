# Notes for the integrator: P8 `memory-mcp` (C08, C05 FR-5..7, C03 follow-up)

- `docs/limitations.md`: A Blocked Codex session stays Blocked until the session goes stale (the host accepts no other Codex event). The Codex watch (`landflow harness watch codex`) is unverified: it was built against Codex's documented rollout records and fixtures, not a live Codex that hit its limit, and the Codex registry entry is `verified: false`. It watches only sessions it started under the watch (files created after it began), sends only a `quota_blocked` event (session id, kind, the provider's message), and a Codex session is always the person's own (it never binds to a Landflow agent). A turn that ends on a limit but writes no `task_complete` error (a crash) is not seen. The memory MCP tools do not add to a team's notebook (notes are written by a team run), and `search_memory` without a space searches projects only (the 20 most recently changed that the caller can open), not teams or agents. The brain's `brain_*` MCP tools and the Brain nodes escape statements in place instead of fencing (their JSON is parsed by clients): the text is safe but not wrapped. Still not fenced: knowledge-base passages, Notion passages from `brain_search_knowledge`, and web results.
