# W4 notes: Spotlight reliability

Docs rows for the integrator.

- `docs/assistant.md`: after a build, the proposal card carries warnings for (a) a connection from one If/Switch output into a node a sibling output also reaches (sent back once like other structural warnings; loops back to the branching node and Merge targets are exempt), (b) a new If/Filter/Switch, or a new Set/Code-like node that is a dead-end stub beside a sibling, that nothing reads ("has no purpose"; shown only, not sent back), (c) a fix that hides an error: `onError: continue`, or code parameters that catch and return (shown only).
- `docs/assistant.md`: when a chat reply says to click Apply and no proposal exists (and none is waiting), Spotlight shows "No change card was created", asks the model once more to call propose_changes, and if it still doesn't says so. Does not apply to test-and-fix sessions, which already press once.
- `docs/history.md` row: "Spotlight reliability: wiring and error-swallowing warnings on proposals, retry when an announced card never appeared".
- `docs/limitations.md`: the purpose check is a heuristic (shaping nodes only, with a sibling); the swallow check reads code by regex.
