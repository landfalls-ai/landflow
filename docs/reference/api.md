# HTTP API

Every route under `/api`, grouped by area. Routes need a signed-in user or an API key (`Authorization: Bearer lf_…`)
unless [Authentication](../features/authentication.md) lists them as public; what each needs beyond that (an API key
scope, an admin role) is set in `apps/web/src/lib/server/auth/policy.ts`. The public API is also published as OpenAPI
3.1 at `GET /api/openapi.json` (Settings → API). Part of the [Landflow docs](../README.md).

| Route | |
|---|---|
| `GET/POST /api/workflows`, `GET/PUT/DELETE /api/workflows/:id` | CRUD; saves are drafts (`active: true` on an active workflow publishes the saved version, as older clients expect) |
| `POST /api/workflows/:id/run` | run (optionally with unsaved `workflow`, `chat`, `items`, and an `idempotencyKey` or `Idempotency-Key` header) and stream SSE events; the run goes on if the request closes (stop it with `POST /api/executions/:id/stop`), except a `debug` run, which stops with it |
| `POST /api/workflows/:id/listen` | listen for a test event `{ nodeId, workflow? }` on a Webhook, Form or MCP Server trigger's test URL for 120 s; SSE: `listening`, then the test run's `execution` events and `result`, or `timeout`, or `stopped` when it listens again elsewhere (closing it stops listening); an MCP listener streams each tool call's run and `listening` again with the pushed-on deadline; 409 while another workflow listens on that URL |
| `POST /api/workflows/import` | `{ data, name?, folderId?, create? }` → `{ workflow, report }`: converts Landflow, n8n or Flowise (chatflow / agentflow) workflow JSON (placeholders for unknown nodes); `create: false` converts without saving |
| `GET/POST /api/templates`, `GET/PATCH/DELETE /api/templates/:id`, `POST /api/templates/:id/use` | the templates library: list (`?search=&category=&source=builtin\|local\|remote&projectId=&page=`; the `agent-teams` category holds every team template, whose summary has `team: { name, faces, picks, members, agents, remote, hasWorkflow }`; `remote.page`, `total`, `hasMore`), save a workflow as a template (`{ workflow, name, description?, categories?, setup?, projectId? }`; `null`: instance-wide) or import a template file (`{ data, projectId? }`), one template (`?format=file` downloads it), edit a saved one (`{ name?, description?, categories?, setup?, projectId?, workflowId? }`), delete it, and create a workflow from one (`?projectId=`, `{ name?, teamName?, folderId?, credentials: { <slot id>: <credential id> } }` → `{ workflow?, team?, agents?, createdTables, warnings }`; a [team template](../templates.md) also creates its agents and team; 409 when its nodes are missing or blocked; a problem of kind `contract`, a broken composite contract, doesn't block it) |
| `GET/POST /api/runbooks`, `POST /api/runbooks/draft` | runbooks from closed Landfall rooms ([runbooks.md](../runbooks.md)): list the workflows tagged `runbook` you can see (`?kind=` an alert title, alertname or kind slug: exact before similar kinds, published before draft; `?projectId=`) → `{ runbooks: [{ id, name, alertKind, room?, steps, approvals, published, updatedAt, url, match }] }`; save reviewed steps `{ name, alertKind, description?, room?, steps: [{ title, approval, reason?, notes }], background?, folderId? }` (`?projectId=`) → 201 `{ workflow, runbook }`, a draft (not active) workflow; fold a room `{ room: { incident, events, outcome? }, alertKind?, name? }` → `{ draft: { name, alertKind, description, room, steps, skipped, background }, existing }` without saving (422 when nothing can be folded). | `GET/POST /api/workflows/:id/evaluations`, `GET/DELETE …/evaluations/:runId`, `POST …/:runId/cancel`, `GET …/evaluations/compare?a=&b=` | offline evaluation runs: overview, start (`{ maxRows? }`), a run with its cases, stop, delete, compare two runs |
| `GET/PUT/DELETE /api/workflows/:id/evaluations/dataset`, `GET/PUT/DELETE …/evaluations/schedule` | the file dataset (multipart `file` or a raw body with `?fileName=`; GET previews it) and the run schedule (`{ enabled, cron, timezone?, maxRows? }`) |
| `GET/PUT /api/settings/ai-caps` | AI usage caps per model credential and per user (`{ credentials, users, allUsers? }`, each `{ dayTokens?, monthTokens?, dayCost?, monthCost? }`), with current usage |
| `GET/PUT /api/workflows/:id/online-evaluations`, `GET/PUT/POST /api/agents/:id/evaluations` | online grading of AI Agent nodes (`PUT { nodeId, … }`) and standalone agents: settings, scores and trend; `POST { sessionId }` grades a session now |

| `POST /api/workflows/:id/versions/:versionId/restore` | restore a version (keeps the current name, tags, folder and active state) and record it as a new version |
| `POST /api/workflows/:id/publish`, `POST /api/workflows/:id/unpublish`, `GET /api/workflows/:id/publication` | publish `{ versionId?, note?, at? }` (default: the saved draft; an older version is a rollback) and unpublish `{ note?, at? }`, each answering the publication, or with `at` (an ISO time in the future) 202 `{ scheduled }` (or `{ approvalRequired, request }` with four-eyes); the publication: the published version, the draft, `hasUnpublishedChanges`, the publish timeline and each app webhook trigger's registration; 422 when the version's composite frames break their contract ([composites.md](../composites.md#checks)) |

| `GET/PATCH /api/projects/:id/settings`, `GET/PUT /api/workflows/:id/policy` | a project's allowed nodes and approvers (`{ nodes?: { mode, plugins, types }, approvers?: default\|admins\|editors\|instance }`, its admins), a workflow's own policy (`{ fourEyes?, nodes? }`, admins of its project) |
