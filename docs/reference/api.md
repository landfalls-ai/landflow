# HTTP API

Every route under `/api`, grouped by area. Routes need a signed-in user or an API key (`Authorization: Bearer lf_…`)
unless [Authentication](../features/authentication.md) lists them as public; what each needs beyond that (an API key
scope, an admin role) is set in `apps/web/src/lib/server/auth/policy.ts`. The public API is also published as OpenAPI
3.1 at `GET /api/openapi.json` (Settings → API). Part of the [Landflow docs](../README.md).

**Background requests.** A request sent with `X-Landflow-Background: 1` (the browser's polls and the editor's edit-lock
heartbeat send it) does not mark its session as used, so it does not hold off `LANDFLOW_SESSION_IDLE_HOURS`;
`GET /api/events` never does. Any other value, or none, counts as use.

**Errors.** A failed request answers `{ error, code, …details }` with the HTTP status: `error` is the text a person reads,
`code` a stable snake_case name (the thrown class's `errorName`, so the same in a production build, or `invalid_request` for a body that failed validation, which also
carries `issues`), and any extra fields the error names (`current` of a workflow conflict, `missing` of a marketplace
lookup). An unexpected error answers 500 `{ error: 'Internal error', code: 'internal_error', requestId }`: never its
message, which goes to the log with the same request id (also the `X-Request-Id` response header, with a W3C `traceparent` beside it on `/api` while a span is active). A write refused
while the Postgres store is blocked answers 503 with `Retry-After`. SCIM routes answer the SCIM error document instead.

| `GET/POST /api/workflows`, `GET/PUT/DELETE /api/workflows/:id` | CRUD; saves are drafts (`active: true` on an active workflow publishes the saved version, as older clients expect). `PUT` takes `If-Match: "<updatedAt>"` (the `updatedAt` you loaded; a body field `baseUpdatedAt` does the same) and answers 412 `{ error: 'This workflow changed since you opened it', code: 'workflow_conflict', current: { updatedAt, updatedBy? } }` when the stored workflow moved on; without either, the last write wins, as the CLI and MCP tools do. `If-Match` takes one entity tag (a list never matches), and the tag is a millisecond timestamp, so two saves in the same millisecond do not conflict. ## Paging and limits

- **Paging.** `GET /api/executions` takes `limit` (an integer 1-500, default 100) and `cursor`, the `nextCursor` of the
  previous page (opaque; pages follow the start time and id, so none repeats or skips a run while new ones start). The
  answer has `nextCursor` only when another page follows. A `limit` that is not an integer in range (`Infinity`,
  `abc`, `0`, `501`) or a cursor that isn't one of ours is 400 `{ error: 'Invalid query', issues }`. Other lists
  validate `limit` the same way: `/api/usage` (max 1000, default 50), `/api/usage/events` (max 5000, default 100),
  `/api/workflows/:id/git-history` (max 200, default 50), `/api/brain/backtest` (max 100, default 10) and
  `/api/executions/:id/events` (max 2000, default 500; `after` an integer from 0).
- **Body size.** A JSON body above `LANDFLOW_MAX_BODY_BYTES` (default 16 MiB) is refused with 413
  `{ error: 'Request body too large', limit }`, by its `Content-Length` or, without one, as soon as the stream passes the
  limit.
- **Rate limits.** In the production profile an authenticated principal may make `LANDFLOW_RATE_LIMIT_API` requests a
  minute (default 600), and each client address `LANDFLOW_RATE_LIMIT_PUBLIC` (default 120) per public trigger group
  (webhooks, forms, hosted chat, MCP triggers, waits). Over the limit: 429 `{ error, code: 'rate_limited', retryAfter }`
  with a `Retry-After` header in seconds. Health checks, plugin announces and `/api/metrics` are never limited. Off in
  development.
