# Observability

Part of the [Landflow docs](../README.md); the [feature map](../README.md#feature-map) lists every feature page.

The host and every plugin are instrumented with OpenTelemetry ([docs/observability.md](../observability.md) is the contract). Each execution is one trace: `trigger.fire` → `workflow.execute` → `node.execute {type}` → `plugin.rpc Execute` → the plugin's `plugin.execute` span and its outbound calls. Agents show model (`gen_ai.chat`), tool and memory runs as children of the agent node. W3C `traceparent` goes to plugins as HTTP headers or gRPC metadata, an incoming `traceparent` is continued, and run/webhook responses return one.

- **Logs**: JSON lines with `trace_id`/`span_id` and, inside an API request, `request_id`, `http.route`, `user.id` and `landflow.api_key.id` (`/api` responses also return `traceparent` when tracing is on); secret-looking keys and secret-shaped values (Bearer tokens, `lf_` keys, URL passwords, private keys, credential values a node was handed) are redacted ([redaction rules](../observability.md#3-logs)); plus a `span.end` line per finished span (`LANDFLOW_LOG_FORMAT=pretty` for humans).
- **Metrics**: Prometheus text at `GET /api/metrics` (executions, node runs, triggers, polls, schedule lag, webhooks, plugin RPCs, heartbeats, plugins online, AI requests and tokens, HTTP durations). The **Record Metric** node (`core.metric`) lets a workflow record its own counters, histograms and gauges as `landflow.flow.<name>`. Each plugin serves its own `/metrics` with execution metrics plus integration metrics such as `landflow.messaging.messages_sent`, `landflow.productivity.records_written`, `landflow.google.sheets.rows_appended` and `landflow.db.query.duration`.
- **Integrations**: every API call or query is a client span under the plugin's `plugin.execute` (`HTTP POST`, `INSERT issues`, `google.oauth.token`), so one run of "GitHub → SQLite → Telegram" is a single trace across the host and three plugins in three languages. Query strings and credential values never reach spans or logs; SQL spans carry the parameterised statement only.
- **AI usage and cost**: every model call's tokens and estimated cost (a price table with Anthropic and OpenAI list prices, Ollama free, overrides in Settings → AI prices) are stored per execution, workflow and agent; the execution view shows them per model, Insights adds a cost column and total, cached tokens are priced (Anthropic cache reads and writes, OpenAI cached input; columns in Settings → AI prices, shown in the execution view and Insights), caps stop runs that go over, also per model credential and per user who started the run, per day or month in tokens or dollars (Settings → AI prices → AI usage caps), and cost alerts tell the alert channels when a cap reaches a threshold such as 80%, once per period ([docs/observability.md](../observability.md#token-and-cost-tracking)).
- **Remote agents**: a call to an agent over A2A is an `invoke_agent` client span whose trace context goes along, so a kagent agent's spans (its controller, Agent Substrate waking the sandbox, the agent's model and tool calls, and its MCP calls back into Landflow) join the same trace; `landflow.a2a.*` metrics count the calls, their tokens and the remote agent's tool calls ([a2a.md](../a2a.md#tracing)).
- **Export**: set `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318` (OTLP/HTTP JSON) to send traces, metrics and logs to Jaeger, Tempo, Loki or the Collector ([docs/otel-collector.yaml](../otel-collector.yaml)); every host log line goes along as an OTel log record (`LANDFLOW_LOG_OTLP`). With `LANDFLOW_TRACE_URL`, the execution view links each run's trace id to your trace UI. On the OrbStack cluster the `orbstack-observability` overlay runs Grafana, Tempo, Prometheus and Loki with an agent-runs dashboard ([deployment.md](../deployment.md#telemetry-on-kubernetes)).
