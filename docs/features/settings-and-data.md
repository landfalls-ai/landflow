# Settings, variables, data tables and insights

Part of the [Landflow docs](../README.md); the [feature map](../README.md#feature-map) lists every feature page.

- **Data tables** (`/data-tables/<id>`): **Import CSV** and **Export CSV** are in the table's **⋯** menu with Rename and Delete; the **+** at the end of the header row adds a column; an empty grid shows its own **Add row**.
- **Settings** (bottom of the rail) lists its sections in five groups: **Workspace** (General, Variables, Alerts, Environments, Source control), **People & access** (Users, API keys, Security, Audit log), **Governance** (Governance, External secrets), **AI** (AI prices, AI caps, MCP) and **Infrastructure** (Workers, Transports). On a phone each group is its own card. Every section opens at `/settings#<id>`, and `?section=<id>` works too. A section says one sentence above its controls; a "?" button or a "How to set up ›" link opens the rest in a small popover (a bottom sheet on a phone). Settings that come from environment variables (SSO, email, queue mode, the claim store) show as one row, "SSO: not configured · How to set up ›", with the variables behind the link; transports that fail with the same error share one banner. **API docs moved** to the **API reference** section of the Developers page (`/developers#api-reference`); the old `#api` and `?section=api` links go there. **AI prices** keeps the built-in table behind "Show built-in prices", and the **usage caps** are their own section, **AI caps**. **Audit log** has two tabs, Log and Configuration (retention, integrity, SIEM streaming), and its filters apply as you change them (only the newest request's answer is shown, and the filters and loaded pages stay when you look at Configuration and come back). **General** keeps the experimental json-render switch under Advanced, and "Prune now" is in the ⋯ menu.
- **Settings → General**: the instance's default time zone (schedules, Date & Time nodes and the days in Insights; until you pick one, `GENERIC_TIMEZONE` or the host's) and execution retention. Retention keeps at most N finished executions (default 300) and/or drops those older than D days (0 = off). It applies at boot, every hour and every `LANDFLOW_RETENTION_EVERY` finished runs (default 50, minimum 1: `0` or a fraction means every run), so the count can exceed the cap by up to that many minus one between passes; the prune runs in SQL on columns and never loads the history, and never touches running or waiting executions; **Prune now** applies it on demand. The page's stored and prunable counts are counted in SQL too. Stored in the database.
- **Settings → Variables**: instance-wide string values (in the database, keys like `API_BASE`). Read them as `{{ $vars.API_BASE }}` in any expression, as `$vars` in the Code node and in AI tool parameters. Unknown names resolve to `undefined`. **Project variables** (a project's **Settings** tab, or the picker on Settings → Variables; `/api/projects/:id/variables`, migration 1400): a project's own keys and values, read before the instance's of the same key in that project's workflows and agents; its members read them, its editors and admins change them, and they can have values per environment too. `GET /api/variables?workflowId=` lists what `$vars` sees in a workflow (project variables marked with `projectId`). Variables aren't secrets; keep secrets in credentials (or an external secrets provider). With environments, a variable can also hold a value per environment (below the list: **Environment values**).
- **Personal preferences**: settings that belong to you, not the instance, kept on the server so they follow you to another
  browser: **Show developer details** (`developerDetails`, off; the user menu's switch: with it off, ids, type ids, transports, languages, trace ids, mode chips and model, tools and token lines are hidden; see [Developer details](../ui-review.md#developer-details)), **Keep my conversations** (`keepConversations`, on, also a switch in the user menu; turning it off asks once whether to delete the ones you have; see
  [Conversation history](../assistant.md#conversation-history)) and how you want your briefing delivered
  (`briefingDelivery`: none, Slack or email). `GET/PATCH /api/me/preferences` (session only); the browser caches them in
  localStorage for the first paint and the server wins.
- **Data tables** (rail): tables of typed columns (string, number, boolean, date) plus `id`, `createdAt` and `updatedAt`. The grid edits cells in place, adds, renames and deletes columns, and searches, sorts, pages, deletes selected rows and imports or exports CSV. The **Data Table** node (`core.dataTable`, usable as an AI tool) inserts, gets, updates, upserts and deletes rows, with all/any conditions (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `contains`, `isEmpty`, `isNotEmpty`), mapping columns one by one or straight from the input, and a dry run. A run that writes to one table is all-or-nothing. A workflow only uses its own project's tables: another project's table fails the node ("Data table “X” belongs to the “P” project"), and the node's pickers list the tables of the workflow being edited (the Evaluation Trigger's dataset picker and the Data Table tool of an agent do the same, for the workflow's or the agent's project; an evaluation reads the workflow's project's table). **Table names are unique within a project**, not across the instance: two projects may each have a "Customers"; a rename or a move into a project that has the name is refused (409), and when a deleted project's or a removed user's tables move into a project that already has the name they become "Name 2", "Name 3"…; a node that names a table finds the one in its own project first. Rows live in the database (one row per table row, written row by row), at most 50,000 per table; the JSON-file storage (one file per table, also capped at 32 MB) remains as an alternative backend.
- **Insights** (**Runs** → **Insights** tab): runs, failed runs, failure rate, time saved and average run time for the last 24 hours, 7 or 30 days against the period before (a change is shown only when the number moved); runs per hour or day; and a sortable row per workflow. The **Agent layers** card appears only when the response cache or the model router answered something in the period, and how Insights are counted is behind **How these are counted** at the bottom. The **AI** tab next to it shows AI spend and the caps ([llm-gateway.md](../llm-gateway.md#the-ai-page)). Manual runs (editor and chat tests) are left out unless **Include manual runs** is on. Time saved = successful runs × the workflow's minutes saved per run (`settings.timeSavedMinutes`, editable in the table). Counts come from a rollup (`.data/insights.json`; in queue mode one per process, added up) updated as each execution is saved, so pruning executions doesn't change them. It is filled from the stored executions on first boot and keeps 400 days.
- **What Landflow knows** (the gear in the [Brain page](../second-brain.md#the-brain-page)'s activity bar, or, when the brain is empty, the links on the index; see the Brain page): the [second brain](../second-brain.md)'s ledger, facts and detectors, a search over what it learned, **Run now** (owners and admins) and **Create the Platform analyst**. Its suggestions appear on Home and on the canvas.
