# Files and binary data

Part of the [Landflow docs](../README.md); the [feature map](../README.md#feature-map) lists every feature page.

Items carry files next to their JSON: `item.binary.<name>` is a reference (`{ id, mimeType, fileName, fileExtension, fileSize, fileType }`), never the bytes, so files of any size move through a workflow without bloating executions ([docs/protocol.md §11](../protocol.md#11-binary-data)). The bytes live in the **binary store**: `<data dir>/binary/<execution id>/` by default, or S3 / MinIO with `LANDFLOW_BINARY_STORE=s3`. Files belong to their execution and are deleted with it (retention, **Delete**, or an hourly sweep of orphans).

- **Nodes**: Read/Write Files from Disk (only under `LANDFLOW_FILES_DIR`), Extract from File (CSV, XLSX, ODS, HTML tables, JSON, text, PDF text, base64), Convert to File (CSV, XLSX, ODS, HTML, JSON, text, base64 → file; XLSX and ODS are written without dependencies, with typed cells (numbers, booleans, ISO dates as date cells, text), an optional bold header row, a **Columns** list, a **Sheet Name**, and **Sheet Name From Field** for one sheet per field value; Extract from File reads a sheet back by name), HTTP Request (Response Format **File**, autodetected for PDFs, images and octet-stream; multipart bodies with item files or one file as the raw body), Respond to Webhook (**Binary File**), and nodes like Edit Fields, Merge and Loop Over Items keep the files of their items. The Code node reads and creates files too (`this.helpers.getBinaryDataBuffer` / `prepareBinaryData`, in both the sandbox and in-process; see "Code node").
- **Uploads**: the Webhook trigger stores multipart files (`files[]` → `files`, several → `files0`, `files1`…) and non-text bodies (or any body with **Raw Body**) as `item.binary`; Form Trigger and Form pages have a **File** element. Uploads past `LANDFLOW_BINARY_MAX_BYTES` get 413.
- **Plugins** read and write files through the host's `/api/binary` with a short-lived token that comes with each call; the SDK helpers hide that: `ctx.helpers.getBinaryDataBuffer` / `prepareBinaryData` (TypeScript), `ctx.BinaryBytes` / `ctx.PrepareBinary` (Go), `ctx.get_binary_bytes` / `ctx.prepare_binary_data` (Python). Small files (≤ 64 KiB) can travel inline. Gmail sends item files as attachments; Telegram uploads photos, documents, audio and video and downloads files; Slack uploads item files to a channel or thread and downloads files. Google Drive uploads item files (streamed through a resumable session past 5 MB), downloads files as binary, and Drive, Sheets and Docs export to PDF, Word, Excel, OpenDocument and more; Gmail also downloads attachments. Send Email, Discord, WhatsApp (media upload and download), Twilio (media and recordings), the Telegram Trigger, GitHub (files, release assets, archives), Jira and Airtable attachments, Notion file uploads, HubSpot files and RSS enclosures all move files too; SQL nodes map bytea/BLOB columns to files; Render Template can output a file and Regex Extract and the py-insights nodes can read text files.
- **UI**: the run view's **Binary** tab lists each item's files with a preview (images, PDF, audio, video, text) and a download link. Video and audio play in place and can seek, because `GET /api/binary/<id>` answers single HTTP `Range` requests (`bytes=a-b`, `a-`, `-n` → 206 with `Content-Range`; 416 when unsatisfiable; multi-range or malformed headers get the whole file) on both the filesystem and the S3 store (a ranged `GetObject`).
