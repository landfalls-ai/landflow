# Integrations

Part of the [Landflow docs](../README.md); the [feature map](../README.md#feature-map) lists every feature page.

The integrations people use most in n8n, chosen from its catalogue and public usage data ([research](../research/04-n8n-integrations.md)), are built as plugins, one per language family, with n8n's resource → operation shape, names and options (Return All / Limit, Simplify, live pickers, usable as AI tools):

Run them with `pnpm plugin:messaging`, `plugin:productivity`, `plugin:google` and `plugin:databases` (all included in `pnpm dev:all`). The last three are the [alert triage](../triage.md) plugins: they install from the repository's marketplace with their flows, or run with `pnpm plugin:landfall`, `plugin:triage` and `plugin:threat-intel` (not in `dev:all`). Every credential has an overridable base URL or host, so each plugin's tests run against local fakes of the service; no test needs a real account.

**Credentials.** Plugins declare credential types (fields, secrets, a connection test) in their manifest. The host keeps saved credentials in an AES-256-GCM vault (`.data/credentials.json`, key from `LANDFLOW_ENCRYPTION_KEY` or a generated `.data/encryption.key`). Workflows only reference them by id, the API never returns secrets, and each Execute call carries just the decrypted credentials that node declared. The **Credentials** page and the picker at the top of a node's parameters create, edit and test them ("Authenticated as @landflow_bot"). The SDKs mask credential values in logs, span attributes and error messages.

**OAuth2 (Connect).** The host's **OAuth2 API** credential (`core.oAuth2Api`) and every plugin type that `extends` it (Google OAuth2 does) have a **Connect** button: it runs the provider's consent page in a popup (authorization code with PKCE, or plain authorization code; signed `state` and a per-flow cookie), stores the tokens encrypted, and shows "Connected as alice@example.com" with the expiry. The client credentials grant gets its token with **Get token** (or at first use). Presets fill in Google, GitHub, Slack, Microsoft, Notion, Discord, HubSpot and Airtable. The plugins ship OAuth2 variants of their token credentials, with the provider's URLs and default scopes fixed: Google OAuth2, Slack OAuth2 (bot scopes), Discord OAuth2 (`identify guilds`, plus an optional bot token for channel calls), GitHub OAuth2, Notion OAuth2, Airtable OAuth2 (PKCE), HubSpot OAuth2 and Jira Cloud OAuth2 (Atlassian 3LO: the node looks the site's cloud id up and calls `api.atlassian.com`; chosen with the Jira node's **Jira Version: Cloud (OAuth2)**). Their nodes have an **Authentication** switch (token, the default, or OAuth2) and also accept whichever of the two credentials is set. Register the **Redirect URL** the dialog shows with the provider: `<LANDFLOW_PUBLIC_URL>/api/oauth2/callback` (override with `LANDFLOW_OAUTH2_REDIRECT_URL`). Nodes get a fresh `accessToken` on every call: the host renews tokens that expire within a minute, and when a node fails with a 401 it renews the token and runs the node once more; a token that can't be renewed fails the node with "reconnect it in Credentials". **Refresh now**, **Reconnect** and **Disconnect** are in the dialog; the Credentials list shows connected / not connected / expired. The **HTTP Request** node's **Authentication** (Generic credential type: OAuth2, Bearer token or header auth) uses them. Protocol details: [docs/protocol.md](../protocol.md#oauth2-credentials-extends).

**Polling triggers.** A node with `triggerSource: "poll"` is called by the host every `pollInterval` seconds with the state it returned last time, and a run starts only when it returns new items. The first poll records a baseline, so activating a workflow never replays history; **Execute** in the editor shows the latest few items. The node panel shows the poll status (last poll, new items, errors) with **Poll now**.

**Activity items.** The integrations that report what people do (Slack, Google Drive and Calendar, Notion) output one shape, the [activity item](../protocol.md#16-activity-items): a stable `sourceId`, URL, author email, time, a suggested event kind (`work.discussion`, `work.doc_edited`…), title, a summary of at most 600 characters, team, initiative and customer hints, and the trimmed vendor object. Each has a trigger (an app webhook where the vendor can call Landflow, else a poll with a cursor whose first poll replays nothing) and a **List Changed Since** operation for backfill and catch-up, so one flow can record any of them.

**App webhook triggers.** A node with `triggerSource: "appWebhook"` registers a webhook at the service when its workflow is published and removes it when it is unpublished, so events arrive as they happen instead of on a poll. The TypeScript, Go and Python SDKs check GitHub (`X-Hub-Signature-256`), Stripe (`Stripe-Signature`, with a timestamp tolerance) and Slack (`X-Slack-Signature`) signatures in constant time ([docs/protocol.md §12](../protocol.md#12-app-webhook-triggers)).
