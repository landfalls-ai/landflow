# Known limitations

What Landflow does not do yet, or does only partly. [roadmap.md](roadmap.md) records what each wave built and the
items still open (its "Wave 6" section); this page is the short list to check before relying on a feature.

- **Isolation**: expressions and in-process Code nodes run in `node:vm` with timeouts. That is not a security boundary. Code you don't trust belongs in the code runner's container (see [deployment.md](deployment.md#code-runner)); started with pnpm, the runner only has OS limits.
- **Scaling out**: [queue mode](features/engine.md#queue-mode-workers-and-high-availability) runs several mains and workers, but every process keeps the whole database in memory (Postgres mode), Valkey Sentinel and Valkey Cluster give failover but not scale-out (every queue key shares one hash tag, so the queue lives on one node), and with `LANDFLOW_CONFIG_STORE=files` the files in the shared data directory are last-writer-wins. Checkpoints add a write per node run (Postgres mode also appends it to the spool). The SQL Data Tables storage still caches a table's rows in memory when it is used (50,000 rows per table).
- **Sign-in**: without queue mode, sign-in rate limits and edit locks live in the host's memory (a restart clears them; in queue mode the limits are shared through Valkey and every main keeps the locks in step). The per-IP limits trust `X-Forwarded-For`, so a public install belongs behind a proxy that sets it. The instance MCP server is scoped to a project only through a project URL or a project token (the unscoped one sees what its user sees).
- **Integrations are tested against fakes**: every plugin's tests use local fakes of the service. The databases plugin is the exception: its integration tests run the Postgres, Postgres Trigger, Redis and MySQL nodes against the infra stack's real servers ([deployment.md](deployment.md#integration-tests-databases-plugin)). Switch and Text Classifier have a fixed set of outputs (4 plus a fallback): ports can be shown or hidden by parameters, but not repeated per rule. Stripe, Slack, GitHub and Microsoft Teams were checked against local fakes only, and Slack's Events URL is pasted into the Slack app by hand.
- **Not yet built**: webhook-based triggers for apps other than GitHub, Stripe and Slack (the others poll; the protocol and SDK signature helpers are ready, [protocol.md §12](protocol.md#12-app-webhook-triggers)), remote model/memory providers over the protocol (tools already work remotely), mDNS discovery, n8n v3-style engine-driven agent steps, file uploads in a standalone agent's test chat, and MCP subscriptions (they need a 2026-07-28 client). Telegram, WhatsApp Cloud, Twilio, SMTP and the databases have no OAuth2, so their credentials take tokens or passwords.
- **Alert triage and Landfall** ([triage.md](triage.md)): the Landfall node and trigger were built from Landfall's API and checked against a local fake (`pnpm fake-landfall`), not a live Landfall; the same goes for the seven threat intel services, tested against `httptest` fakes. The Landfall Trigger polls. Triage's quality depends on the model and the rules; that is why it starts in Shadow mode. Runbooks from closed rooms ([runbooks.md](runbooks.md#not-built)) are folded by fixed rules from a room you paste or pass in, into form-wait steps for people, not generated action nodes; nothing makes one by itself when a room ends, and the folding was checked against fixtures, not a live Landfall. Flow share pages need a signed-in member of the instance; they aren't public links.
- **Deployment and the gateway**: the KEDA worker example (`deploy/k8s/examples/keda`) has not been applied, since KEDA is not installed on the local cluster. With the identity provider accepted on a gateway route (`components/gateway-landflow-tokens-idp`), the gateway's own 401 carries no `WWW-Authenticate` challenge.
- **Spotlight on the local model**: `qwen3-coder:30b` doesn't always follow the brevity rule (it may still write a numbered list). The guards against "it has been added" and made-up ids match common wordings and id-like parameter names ([assistant.md](assistant.md#the-builder-chat)), not every case, so a proposal card is still the thing to read before Apply. [Test and fix](assistant.md#test-and-fix) leans on the same model: a flow it drafts often has empty filter conditions or Set fields, and a fix can take a few rounds or run out at 4 (one trial spent all 4 on an Aggregate node's fields). The same prompt can pass in one session and fail in the next. Its checks are structural (a node failed, nothing reached the end, a step with no conditions or fields) plus the model's own reading of the output against the goal, so a run it calls ready is worth a look before publishing. A proposal still waiting is matched by node type and name, so the same job under another name isn't recognised, and the same goes for a node added back after a pending proposal removed it (a summary first done by a Basic LLM Chain and then by a Code node gets through; a node the latest message asks to add by that name, "remove Check and add a new Check after Code", is let through); the check against an If or Filter after a node that already branches looks only at nodes added or connected without an explicit output; Code nodes have no usable `$runIndex`, so a round counter keeps its number in a field. Adding a node `after` one that already feeds another leaves that old connection in place without a warning (a v2-to-v3 trial kept Tech Lead → Open draft PR).
- **Composite nodes** ([composites.md](composites.md#not-built)): no governance rule can require a composite yet (for example "AI calls only inside an AI step"). A frame's fallback is picked in its contract panel, not drawn as an edge. A frame's timeout is checked when each node inside starts, so a node already running isn't interrupted. Composite types saved on an instance (`local.<name>`) aren't part of Git sync or environment promotion: on another instance a frame typed by one shows the type as unknown until it is saved there too.
- **Remote agents over A2A** ([a2a.md](a2a.md#not-built)): a remote agent's tokens are recorded but don't count toward an agent's AI limits. Landflow calls agents over A2A but doesn't serve A2A itself, and uses neither push notifications nor the gRPC and REST bindings. The dialog doesn't preview the agent card. kagent 1.0.0-alpha17 drops the `landflow.*` message tags instead of copying them onto its spans, parents its MCP calls back into Landflow on a span it never exports (they show as separate roots of the same trace), marks its stream spans as errors when a stream closes, and elides message content in its logs. kagent runs in a kind cluster beside the OrbStack one, since Agent Substrate needs Kubernetes 1.37. An agent deployed to kagent ([a2a.md](a2a.md#landflow-agents-on-kagent)) gets its persona, model and tools but not cross-session memory, guardrails or usage limits; its sessions on kagent don't show in Landflow's Sessions tab, and drift from an edit made in kagent shows when the status is read, not as it happens. On kagent's Claude Code runtime ([a2a.md](a2a.md#on-claude-code)), Substrate can't fetch git or bucket plugin sources (its golden snapshot has no egress), so Landflow packs plugins into images it serves itself, from GitHub marketplaces only; the Harness image has only bash and git; and qwen3-coder through Ollama keeps calling its hand-in tool after the task is done. kagent compiles in Claude Code 2.1.285 and refuses any other version, so `landflow-claude-dev` runs the latest Claude Code behind a wrapper that answers `claude --version` with the pinned one. The landflow-harness mod ([a2a.md](a2a.md#the-landflow-harness-mod)) reports a Claude Code agent's real usage (in queue mode the main it posts to passes it on to the worker that made the call, and a batch for a worker that has gone is lost), only for new requests (an answer to a paused task is estimated), and only where the credential names a Plugin Registry and Landflow's access Role may write EgressPolicies (the mod reports through one of its own per agent); its guard is set per agent at deploy time (read-only, normal or report only; a request can only tighten it) and, in Normal mode, asks a person only about a push to main or master, a force push and deleting a remote branch (nothing else is askable, the answer is read by polling for up to 10 minutes, and an ask posted to a worker's trace that has gone is never answered until it times out), and its rules match command lines, so a script that does the same thing gets past them, read-only included. A node's live progress (`node.progress`, [a2a.md](a2a.md#the-a2a-agent-node)) is kept in memory: by the process that runs the execution and, in queue mode, by every main from the relayed events, so a main that starts mid-run shows a node's steps from its next report, and a tool sub-node that has not reported yet lights up only from its `node.started` event. The execution view's **Agent session** panel polls every 2 s (no push) and shows only sessions saved since the link was added; a running session is saved at most every 1.5 s, so the newest step can lag a moment. The **Run an Agent** node ([agents.md](agents.md#from-workflows)) refuses tools that need approval, since a workflow run has nobody to approve them, and runs every agent on Landflow's runtime, also one deployed to kagent (the A2A Agent node calls kagent, without the canvas's tools).
- **Second brain** ([second-brain.md](second-brain.md#limits)): its vector collections (`landflow-brain-<project>`) aren't access-controlled by themselves (the routes and nodes search only the caller's projects, but a Vector Store node pointed at one reads it). Dead weight waits until the ledger reaches back 60 days, and the backfill only reaches as far as the executions and audit events on disk. In queue mode each process starts On Usage Event workflows for the events it recorded, so a batch holds one process's events. Ollama calls cost $0, so the AI-cost detector never suggests a smaller local model. The model writes fixes and drafts one at a time, so a study or detect run on a slow local model takes minutes (`POST /api/brain/run` waits). It proposes and never applies by itself; acting alone on low-risk changes waits for Spotlight's action layer.
- **Agent workspace and architect** ([agents.md](agents.md#agent-architect)): the Agent architect designs new agents only (not changes to an existing one), on the assistant's model with no picker, and a local model's drafts need checking (it may still pick odd tools). Agents and teams export as Claude Code plugins ([marketplace.md](marketplace.md#export-agents-as-plugins)), but schedules, channels, credentials and workflow tools stay behind, and Claude Code itself ignores Landflow's node, MCP and knowledge tools. A team template ([templates.md](templates.md)) holds one flow at most, makes a second slot for a credential the agents and the flow both use, drops a workflow tool that points outside the template, and copies a sub-agent only through the agents' tools and Run an Agent nodes (not through other flows). The built-in **Plugin builders** team template keeps its Claude Code members as A2A addresses of this machine's kagent (you point them at your own after using it) and the GitHub nodes' `your-org`/`your-repo` placeholders. Marketplace installs put their agents in the default project. A Missing tool suggestion's **Build it** starts the workflows that build the tool, but none ships yet: the agents and flow that write the plugin are in progress ([roadmap.md](roadmap.md#building-tools-from-suggestions-in-progress-2026-10-31)).
- **Network and toolchains on kagent** ([a2a.md](a2a.md#not-built)): the package EgressPolicy grants the package cache (`landflow-cache`: npm, Go, PyPI and Alpine, with no authentication) to every agent that references it, and `landflow-github` gives every agent that references it its token's whole reach. What an agent may push (its branch only, never main, no merges) is in its instructions, not enforced: scope the token to the repository and protect `main` with a branch rule. On `landflow-claude-dev`, Go's standard library is pre-built but a project's own packages compile on every session, and its dependencies are installed on every session (from the cache, so only the first fetch goes out). The image is loaded into Landflow's store by `claude-harness-dev.sh` (a script, not a page).
- **GitHub MCP tools for agents** ([a2a.md](a2a.md#githubs-mcp-tools-for-agents)): two access levels (read; read and review) over an allow-list of the pinned server's tools (github-mcp-server v2.0.2; a renamed tool in a later version is simply not offered until the list is updated); the token's repository scope is the only per-repository limit; a review comment is written to GitHub when the tool is called (approval is the only gate); the server runs in the OrbStack cluster only (no compose service) and takes the token from each request, which was checked against the image but not against GitHub with a real token.
- **GitHub plugin**: no delete (repositories, branches or files), no marking a draft pull request ready (GitHub's REST API can't; open it ready to merge it), no review or check-run operations, no GitHub App JWT flow (use an installation token) and no OAuth2 credential. Files: Commit adds or replaces regular files (mode 100644); it can't delete or chmod them, and it doesn't retry when the branch moved meanwhile (GitHub refuses the non-fast-forward update with 422; run it again). Its **GitHub** node shares a display name with Productivity's (`github.github` and `productivity.github`). **Compare** lists at most 300 files, with no patch for large or binary files.
- **Run Trace** ([run-trace.md](run-trace.md#not-built)): a Claude Code agent on kagent reports its usage, cost and guardrail stops through the landflow-harness mod, and its first 300 model requests per call are spans of their own; the OTLP export (`LANDFLOW_OTLP_TRACES_URL`) is JSON, sent once when a run ends, and Claude Code's own spans aren't joined by trace id yet; run search matches the stored text with `LIKE` (no ranking), reads at most 1,000 candidate runs a request and finds only runs that have a journal, and a run profile can't define measures over time of its own. **Content kept** is set per workflow, not per project. Claims come from a structured block or the profile's patterns, never from a model reading the reply. The checks see only what the journal recorded, so a tool that fails with exit code 0 passes. Models and memory sub-nodes can't report artifacts or checks. An agent's connections are what the flow and its published settings said when its span started, and a kagent agent's runtime is told from its deployment, not read from the cluster. A trace rebuilt for a run recorded before Run Trace has no progress notes, artifacts, checks or decisions. Code changes come from `Write`, `Edit` and `MultiEdit` steps only (not `sed -i` or a generator), a file over 32 KB (16,000 characters per argument from a remote agent) shows incomplete, a run recorded before 2026-10-31 shows most remote agents' files only from the branch, a run recorded before the same fix shows a flow's agent twice on the Team tab, and "pushed" is read from the agent's own `git add`/`commit`/`push`; line comments on diffs live in one browser (not shared, and they reach the agents only through a Run report's Send back), and an HTML page's own images, styles from other servers and scripts don't show in its preview. A delegating call without a `reason` still runs; members' words come only from text a later artifact follows; rounds start at the first node that ran again; fix cycles need a profile that names check commands, and their error counts are parsed from output text. A lead's claim about its team's work isn't credited with the team's steps, so it shows as a warning.
- **Agent teams** ([agent-teams.md](agent-teams.md)): only a Landflow agent can lead or manage (remote members are leaves). A reviewer's verdict is read from a `VERDICT:` line only (an approval in other words counts as asked, not approved), and a reviewer that manages the member it reviews isn't held to it. A remote agent that reports no usage (one without the landflow-harness mod) is budgeted on an estimate from what crossed the wire, a floor that stops it late; the lead and agent members are counted after each model call, but a remote member's usage counts against its budget when its answer comes: what its mod reports mid-task only moves its bar. A tool that needs approval pauses a team run for a person, and so does a member's question, but only in a flow (elsewhere the tool is refused and the run ends in Needs a person); the tools of a Claude Code member on kagent are still refused. Only Landflow agent members can consult a peer or hand a task over (a remote member has no tools to do it with), a chain of consults stops after two, and the model decides when to consult. A manager's answer is checked for file names, commits, test counts and pull requests nothing gave it, not for results described in words, and it is sent back once (an answer that still names them stands, with a warn check). A model that ignores the send-back keeps its invented details: the local `qwen3-coder:30b` lead did, in the Tech Review flow. A person can pause a member and take over ([run-trace.md](run-trace.md#pause-and-take-over)), but the pause is held in the memory of the process running the execution (lost on a restart, and unreachable from another process in queue mode), an agent stops between steps rather than inside a model call, and a remote member can only be stopped and redirected (its cancelled task's work may be lost). **Ask this member again** goes through the lead, which is a model told to ask only that member.
- **Team notebook** ([team-notebook.md](team-notebook.md#not-built)): search by meaning needs Ollama's `nomic-embed-text`; without it search matches words only. A note is embedded once, so changing the model setting does not re-embed old notes. A note counts as from outside after any web or fetch tool in the same run, whether or not the author used what it read. A remote member's note shows on the canvas only when its A2A task reports the MCP call as a step. The open calls that bind a kagent member's notes to a run live in the memory of the process running the execution, so in queue mode a worker's runs are not seen by the main that serves the MCP request. Person actions follow the team's access, with no separate permission for verifying or promoting. kagent's own runtime lists note tools only after the agent is redeployed.
- **Local telemetry stack** ([deployment.md](deployment.md#telemetry-on-kubernetes)): `landflow-lgtm` keeps everything in an `emptyDir`, so a restart loses it. The dashboard's totals use `increase()`, which can't see the first increment of a new series: after a host restart the first run, approval or call of each kind isn't counted in the stat panels (traces and logs have every one).
- **By design**: a Respond to Webhook reply built from a secret is not redacted: redaction covers what is kept, and the reply is sent, not kept ([External secrets](features/secrets-and-environments.md)).
