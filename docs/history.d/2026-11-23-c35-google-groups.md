section: 2026-11-23: access requests
| (this change) | **Google group grants (C35, Google part).** The Google Directory node gained a Group resource (Get, Get Many) and a Group Member resource (Add, Remove, Get Many, Has Member, Update Role) over the Admin SDK Directory API, the grant action of an access request for a Google group. Add and Remove are idempotent in effect: someone already in the group (Google's 409) or not in it comes back with `changed: false`; every operation outputs `{group, member, role, status, changed}`. Errors say \"No group …\", \"No user …\" or, for a 403, that an admin must be impersonated and which scope to delegate (the node asks for the narrowest scope of each operation: the `.readonly` group and member scopes to look, `admin.directory.group.member` to change). The writes are not agent tools and the node refuses them in tool or MCP mode, keys must be an email or an id, Add reports `alreadyHad` and never changes an existing role, and Has Member falls back to direct membership where Google answers 400 for an outside address. The fake Directory is now stateful (groups and members, scope and admin checks, `POST /_fake/directory/groups`). | [features/integrations.md](features/integrations.md) |
