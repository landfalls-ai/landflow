section: 2026-11-23: access requests
| (this change) | **Access requests, the core (C35, part 3).** People ask for access (a GitHub team, organization, repository or project, a Google group, or something done by hand) for a time, with a reason; the entry's approvers decide, and approval grants the access and Landflow takes it back at the end. A catalog (migration 2935: `access_entries`, `access_requests`, `access_grants`, `access_accounts`) with per-row rules: everyone sees the enabled entries they may ask for, owners edit, only admins create, delete and change what an entry reaches. Two installed templates (`access-requests`, `access-requests-chat`) and three nodes: **Access Request**, **Apply Access Decision** (grants only when the server's own record of the run shows an approver other than the requester approved) and **File Access Request** (an agent tool that files only after a confirmation from a later chat turn). The `access grants` leader service removes grants at their end with retries and an hourly reconcile (drift, overdue). Session-only routes under `/api/access` and a port (`lib/server/access/port.ts`) for a later Landbright backend. **Ask a Person** gained **Answer Choices** (the approver picks a duration) and **People Only** (no API key or MCP answer), both off by default. | [access-requests.md](access-requests.md), [features/engine.md](features/engine.md), [reference/api.md](reference/api.md) |
| (this change) | **Access requests core, review fixes (C35).** A revoke that arrives while an add is in flight is carried out the moment the access is in place; the system is checked once before the first add and `already had` is never worked out again (a retry claims only from `failed`, the hourly pass takes up a stalled `pending` grant); Apply believes only an answer to the question the server built, recorded by the node the request was filed with, by an approver stored at filing; only an instance admin edits, publishes, unpublishes, restores or deletes the installed flows; the sweeper writes only the columns it changes; GitHub Access refuses to raise an existing team member's role or a direct collaborator's permission; one GitHub login per person, shown unverified, and one live grant per target and account; drifted grants still end; indexes on open requests, executions and grants; the access chat files only from its own runs and spends the token; owners may not widen durations. | [access-requests.md](access-requests.md), [limitations.md](limitations.md) |
