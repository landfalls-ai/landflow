# Harden Landflow's runtime before chasing AI parity

Landflow's editor and engine are not where it trails: its breakpoint debugger, any-language plugins, free OpenTelemetry export and local-Ollama flow builder match or beat what n8n, Zapier, Make and Power Automate ship, so what it lacks is the platform around the workflow. The Wave 1 build now under way closes the first tier of those gaps (sub-workflows, error workflows, Respond to Webhook, batching loops, cron schedules, forms and waits that survive a restart, version history, variables, data tables, retention and insights), which the n8n, hosted-platform and governance research all ranked core for n8n parity. The rest fall into four groups that should be built in this order. **First comes a durable runtime layer the roadmap never names**—database storage, recovery of runs interrupted by a crash, pinning each run to a workflow version, idempotency keys and per-workflow concurrency—which Wave 1's pause/resume makes urgent. **Second is the floor for leaving localhost**: sign-in with API keys, a sandboxed Code node, OAuth2, binary data, signed app webhooks and draft/publish, Wave 2 as planned. **Third are the AI features every competitor now has**, led by an MCP client and server that should move from Wave 3 into Wave 2, because every hosted and AI-native rival ships MCP and Wave 1's Execute Workflow trigger makes it cheap; RAG on Ollama embeddings, streaming chat, guardrails, cost caps and evals follow. **Fourth is team governance**, which competitors charge for everywhere and which can wait—except OIDC login and git sync, which n8n paywalls and Landflow can give away. The biggest strategic weakness is no feature at all but a catalogue of about 20 integrations against competitors' hundreds or thousands, and the MCP client and n8n import are the cheapest ways to soften it.

## Landflow's gaps sit around the canvas, not on it

Every hosted rival now ships an AI builder—Zapier's Copilot, Make's Maia (in the Scenario Builder since 12 August 2026) and Copilot-assisted flow creation in Power Automate ([Zapier Help](https://help.zapier.com/hc/en-us/articles/16722578092429-Use-the-editor-to-build-and-view-your-Zap-workflows); [Make 2026 releases](https://help.make.com/2026); [Microsoft Learn](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/))—so Landflow's AI flow builder is expected rather than distinctive. Running it on local Ollama is distinctive: Power Automate's local-model support covers only desktop flows and is in preview, and Zapier offers no admin-level bring-your-own-model ([Microsoft Learn](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/planned-features); [Zapier Help](https://help.zapier.com/hc/en-us/articles/47402591569805-Migrating-from-Agents-to-AI-by-Zapier)). Competitors are still adding runtime debugging that Landflow's breakpoint debugger already surpasses: Power Automate added debugging into condition actions in December 2025 and debugging with variable default values in June 2026, and Make added AI error explanations in July 2026 ([Microsoft Learn](https://learn.microsoft.com/en-us/power-platform/release-plan/2025wave2/power-automate/planned-features); [Make 2026 releases](https://help.make.com/2026)). Zapier's **Next Gen Zaps**, announced on 23 September 2026 and still in early access, add branches that split and rejoin, nested loops and continue-on-failure, and remove the 500-item loop cap ([Zapier Community](https://community.zapier.com/product-updates/the-next-generation-of-zaps-is-here-53832))—semantics Landflow's n8n-style item model already has.

Observability and plugins tell the same story. **Windmill sells OpenTelemetry and Prometheus as Enterprise features** ([Windmill pricing](https://www.windmill.dev/pricing)) and Kestra only added trace propagation in its 2.0 rewrite ([Kestra 2.0](https://kestra.io/blogs/release-2-0)), so Landflow's free OTLP export sets it apart. n8n's community nodes are TypeScript packages from npm, and n8n 3.0 disables unverified packages by default ([n8n 3.0 breaking changes](https://docs.n8n.io/changelog/v30-breaking-changes)); Landflow's out-of-process plugins in any language are more flexible. Its standalone Agents, with skills, sub-agents, per-tool approvals, memory, schedules, Telegram and a Message an Agent node, keep pace with n8n's own Agents preview, which reached self-hosted plans in 2.32.3 ([n8n Agents docs](https://docs.n8n.io/build/build-and-manage-agents)).

The market around Landflow is churning in ways that shape what to build. n8n ships a minor version every week (2.45 landed on 20 October 2026), and its coming 3.0 requires Docker for self-hosting and turns Chat Hub off by default ahead of removing it in 4.0 ([n8n release notes](https://docs.n8n.io/release-notes/); [n8n 3.0 breaking changes](https://docs.n8n.io/changelog/v30-breaking-changes)). **Flowise froze development on 29 July 2026 and archived its repository in August**, saying that "the typical rigid workflow low code approach quickly hits the limit" as developers turn to coding agents ([Flowise sunset](https://flowiseai.com/sunset)). Pipedream Workflows shuts down on 31 March 2027 after Workday agreed to acquire Pipedream ([Pipedream docs](https://pipedream.com/docs/workflows/building-workflows/settings/concurrency-and-throttling); [Workday](https://newsroom.workday.com/2025-11-19-Workday-Signs-Definitive-Agreement-to-Acquire-Pipedream)), Vellum pivoted to a personal assistant, and Lindy now sells an "AI employee" ([vellum.ai](https://www.vellum.ai/); [lindy.ai](https://www.lindy.ai/)). Three lessons follow: importers are cheap acquisition (n8n import is in Wave 1, and a Flowise importer could follow); a ChatGPT-style chat hub is not worth building; and being drivable by external agents through MCP and a CLI now matters as much as the canvas. The weakness no wave addresses is catalogue size—about 20 integrations against Activepieces' 760+ pieces, Lindy's 1,500+ integrations and Pipedream's 3,000+ connectors ([Activepieces](https://www.activepieces.com/docs); [lindy.ai](https://www.lindy.ai/); [Workday](https://newsroom.workday.com/2025-11-19-Workday-Signs-Definitive-Agreement-to-Acquire-Pipedream)).

## Wave 1 closes the first tier of n8n-parity gaps

The research streams that benchmarked n8n, the hosted platforms and team operations put the same items at the top of their lists—sub-workflows, error workflows, Respond to Webhook, cron, version history, waits for human input, data tables and variables—and Wave 1 covers almost all of them. The bar comes from long-standing features elsewhere: Zapier's Sub-Zaps and Make's subscenarios with scenario inputs for callable workflows ([Zapier](https://zapier.com/apps/sub-zap-by-zapier/integrations/zapier-manager/1386110/handle-new-zap-errors-in-zapier-manager-by-calling-sub-zaps-in-sub-zap-by-zapier); [Make Help](https://help.make.com/scenario-inputs-now-available-for-all-users)); Zapier's per-step error handlers and Make's Break, Commit, Rollback and Resume handlers ([Zapier Help](https://help.zapier.com/hc/en-us/articles/22495436062605-Set-up-custom-error-handling); [Make Help](https://help.make.com/error-handlers)); Inngest's `waitForEvent`, Trigger.dev's waitpoint tokens and Windmill's approval steps for waits ([Inngest](https://www.inngest.com/docs/learn/how-functions-are-executed); [Trigger.dev](https://trigger.dev/docs/wait-for-token); [Windmill](https://www.windmill.dev/docs/flows/flow_approval)); n8n's Data Tables with a **200 MiB default per instance** ([n8n docs](https://docs.n8n.io/build/work-with-data/data-tables)); and n8n's pruning, **on by default at 14 days or 10,000 executions** ([n8n execution data](https://docs.n8n.io/hosting/scaling/execution-data/)).

Several Wave 1 items are things n8n charges for. Custom variables are excluded from its free Community Edition, version diff is Enterprise-only, the Insights dashboard starts at Business with only a 7-day summary banner free, and folders require a (free) registered licence ([n8n Community Edition](https://docs.n8n.io/hosting/community-edition-features/); [n8n pricing](https://n8n.io/pricing/); [n8n Insights](https://docs.n8n.io/insights/)); Zapier likewise keeps version comparison for Enterprise ([Zapier pricing](https://zapier.com/pricing)). **Shipping all of these free puts Landflow ahead of n8n's Community Edition the day Wave 1 lands.** The n8n importer has a side benefit too: it turns n8n's public template gallery, whose IDs now pass 13,000 ([n8n template #13271](https://n8n.io/workflows/13271)), into a template source for Landflow, limited only by how many n8n nodes the importer can map—which makes node coverage the importer's key metric.

Wave 1 also creates three obligations the roadmap should record now. Once runs can wait for days and every save creates a version, the engine must decide which version a resumed run executes; resuming on whatever is current silently changes in-flight behaviour, so **each execution should record the version it started on**. Retention must skip waiting runs, just as n8n's pruning never deletes running, waiting, tagged or rated executions ([n8n execution data](https://docs.n8n.io/hosting/scaling/execution-data/)). And Execute Workflow should match n8n 2.0's semantics, in which a parent receives a paused child's final output rather than its input ([n8n 2.0 breaking changes](https://docs.n8n.io/2-0-breaking-changes)), or imported n8n workflows will misbehave. Two smaller editor gaps fall outside Wave 1: Make added canvas undo/redo in May 2026 ([Make 2026 releases](https://help.make.com/2026)), while a search of Landflow's code finds undo only for assistant edits; and Make stores a failed run with its data so a user can fix the mapping and resume from the failed step ([Make Help](https://help.make.com/Overview-of-error-handling)), a pattern that can wait because retry plus error workflows cover the common case.

## Pausable runs expose a durability layer the roadmap omits

None of the roadmap's four waves mentions replacing JSON-file storage, recovering runs that were mid-execution when the process died, idempotency keys, or rate limits and debounce; concurrency limits and automatic retry appear only in Wave 4. Wave 1 changes the urgency, because once runs can wait for days, a single process writing JSON files becomes the system of record for approvals, forms and timers. The durable-execution engines show what this layer looks like. **Every one of them stores each completed step outside the worker and, after a failure, resumes by skipping the steps already done**: Temporal through event history and deterministic replay, Inngest by saving step results under a step ID, Restate through a journal, Hatchet through a Postgres event log, and Trigger.dev through process snapshots ([Temporal](https://docs.temporal.io/evaluate/understanding-temporal); [Inngest](https://www.inngest.com/docs/learn/how-functions-are-executed); [Restate](https://docs.restate.dev/concepts/durable_execution); [Hatchet](https://docs.hatchet.run/v1/durable-execution); [Trigger.dev](https://trigger.dev/docs/how-it-works)). A Landflow workflow is data rather than user code, so it needs none of Temporal's determinism rules. The approach Inngest, Windmill and Hatchet share fits instead: save each node run's output under a stable ID (node name plus run index) before scheduling the next nodes, and rebuild the run from those outputs on restart—the same data Landflow's partial execution already reuses.

### SQLite by default keeps the single-binary install

Engines that depend only on Postgres show that a single-dependency design works: Hatchet is built on PostgreSQL, and in Kestra 2.0 Postgres serves as both queue and repository ([Hatchet](https://docs.hatchet.run/home); [Kestra 2.0](https://kestra.io/blogs/release-2-0)). n8n now supports only Postgres or SQLite and calls its pooled SQLite driver "up to 10x faster" ([n8n 2.0 breaking changes](https://docs.n8n.io/2-0-breaking-changes)), though its queue mode does not run on SQLite ([n8n queue mode](https://docs.n8n.io/hosting/scaling/queue-mode/)). **SQLite by default with a Postgres option** keeps Landflow a single-binary install—an advantage as n8n 3.0 goes Docker-only—and unblocks queue mode, retention at scale and searching executions by their data, which Make added across scenario runs in August 2026 and n8n sells on its Pro plan ([Make 2026 releases](https://help.make.com/2026); [n8n pricing](https://n8n.io/pricing/)). Embedding Temporal or Restate instead would provide durability out of the box but add a service to operate and bring payload ceilings—Inngest caps a step's return value at 4 MiB and a run's state at 32 MiB, and Trigger.dev rejects payloads over 10 MB ([Inngest limits](https://www.inngest.com/docs/usage-limits/inngest); [Trigger.dev](https://trigger.dev/docs/triggering))—so building it in is the better fit.

### Version pinning and idempotency cost little now

**Pinning a run to the version it started on is the norm.** Trigger.dev locks each run to the latest version when it starts and keeps retries there, Windmill pins its workflows-as-code runs, and in Kestra drafts never run while triggers use the last published revision ([Trigger.dev](https://trigger.dev/docs/versioning); [Windmill](https://www.windmill.dev/docs/core_concepts/workflows_as_code); [Kestra 2.0](https://kestra.io/blogs/release-2-0)). For a graph tool, pinning costs one immutable snapshot per version and a `versionId` on each execution. Idempotency is just as cheap and more urgent for webhooks and payments. Inngest deduplicates events by ID for 24 hours and accepts an idempotency expression, Trigger.dev keys expire after 30 days by default, and **no engine promises exactly-once side effects**—all of them tell users to pass a stable key downstream ([Inngest](https://www.inngest.com/docs/guides/handling-idempotency); [Trigger.dev](https://trigger.dev/docs/triggering)). Landflow should deduplicate trigger events on a key expression and send each plugin call an `Idempotency-Key` built from the execution and step IDs.

### Flow control is where Landflow can beat n8n outright

n8n's only concurrency control is an instance-wide environment variable, off by default, with no per-workflow setting ([n8n concurrency control](https://docs.n8n.io/hosting/scaling/concurrency-control/)). Among the most-discussed open requests on its feature-request forum are **automatic retry of workflows (30 replies), concurrency in workflow settings (26) and blocking parallel runs (12)** ([n8n feature requests](https://community.n8n.io/c/feature-requests/5?order=votes)). The developer engines go much further: Inngest offers eight controls (concurrency, throttling, rate limiting, batching, singleton, debounce, priority and per-tenant keys), and Trigger.dev and Hatchet set limits per tenant through a key expression ([Inngest](https://www.inngest.com/docs/guides/flow-control); [Trigger.dev](https://trigger.dev/docs/queue-concurrency); [Hatchet](https://docs.hatchet.run/v1/concurrency)). Two lessons carry over. Paused runs must release their concurrency slot, as they do in Inngest and Trigger.dev, or a few long approvals will block every other run of a workflow. And queues must be durable and bounded; Pipedream's docs warn that events beyond the queue size "will be lost" ([Pipedream](https://pipedream.com/docs/workflows/building-workflows/settings/concurrency-and-throttling)). The minimum for Landflow is per-workflow concurrency with an optional key expression, a singleton mode, automatic retry of failed runs with backoff, per-node timeouts and a stop-all control like the one n8n added in 2.3 ([n8n release notes](https://docs.n8n.io/release-notes/)); Landflow can already cancel a single live run. Debounce, batching and rate limits can wait for the AI wave.

## Leaving localhost requires sign-in, sandboxing, OAuth2 and files

Wave 2 as planned is right, because its items are where Landflow falls below what self-hosted competitors give away. **Running with no login is below every self-hosted competitor's free tier**: Kestra's open-source edition has a single basic-auth account, and Windmill's Community Edition allows 50 users, 10 of them with SSO ([Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid); [Windmill pricing](https://www.windmill.dev/pricing)). Free OIDC is a cheap differentiator, because n8n reserves OIDC for Enterprise and SAML for Business and above ([n8n OIDC](https://docs.n8n.io/user-management/oidc/); [n8n SAML](https://docs.n8n.io/user-management/saml/)). API keys should carry scopes from the start, since outside Enterprise n8n's keys "have full access to all the account's resources and capabilities" ([n8n API auth](https://docs.n8n.io/api/authentication/)). The roadmap misses one item that becomes essential the moment a second user exists: an edit lock or conflict detection, which n8n handles by letting one person edit a workflow while everyone else sees it read-only ([n8n support](https://support.n8n.io/article/understanding-workflow-publishing-in-n-8-n-2-0)).

The Code node's use of `node:vm` is a liability, since the Node.js docs state that `vm` is not a security mechanism ([Node.js vm](https://nodejs.org/api/vm.html)). n8n 2.0 made out-of-process task runners the default, blocked environment-variable access from Code nodes and disabled Execute Command by default ([n8n 2.0 breaking changes](https://docs.n8n.io/2-0-breaking-changes)), and Windmill isolates jobs with nsjail and PID namespaces ([Windmill](https://www.windmill.dev/docs/advanced/security_isolation)). Landflow can reuse its plugin protocol here, running user code in an out-of-process runner plugin with CPU, memory, network and time limits; a Python runner comes almost free from the existing Python SDK. n8n 3.0's runner timeout of 60 seconds, down from 300, shows how tight the defaults are getting ([n8n 3.0 breaking changes](https://docs.n8n.io/changelog/v30-breaking-changes)).

**OAuth2 "Connect" buttons decide whether non-developers can use the integrations at all**, and Make went further in February 2026 with credential requests that let a colleague authorise a connection on someone's behalf ([Make Help](https://help.make.com/introducing-credential-requests)). Instant app triggers need a register/unregister lifecycle and signature checks: n8n added signature verification to many triggers in May 2026 and an "Only Run If" webhook filter in 2.28 ([n8n release notes](https://docs.n8n.io/release-notes/)), and Make offers authenticated webhooks plus mailhooks that turn an email address into a trigger ([Make webhooks](https://help.make.com/webhooks); [Make Waves '25](https://www.make.com/blog/waves-make-product-releases-2025)). An inbound-email trigger is not on the roadmap and belongs in this wave.

Binary data should target object storage from the first version. n8n removed in-memory binary storage in 2.0, and its queue mode needs S3 because workers cannot share a filesystem ([n8n 2.0 breaking changes](https://docs.n8n.io/2-0-breaking-changes); [n8n queue mode](https://docs.n8n.io/hosting/scaling/queue-mode/)); Trigger.dev moves any payload over 512 KB to object storage ([Trigger.dev](https://trigger.dev/docs/triggering)). Landflow items should carry a reference (`binaryRef`, MIME type, size) rather than bytes, with large JSON outputs taking the same route. Files unblock later work: PDFs and images as LLM inputs (n8n agents have passed binary PDFs to models since 2.28 ([n8n release notes](https://docs.n8n.io/release-notes/))), form uploads and RAG loaders. Draft/publish should ship together with version pinning, since the two form the safe-deploy model n8n made default in 2.0 ([n8n 2.0 breaking changes](https://docs.n8n.io/2-0-breaking-changes)).

The CLI and public API deserve treatment as a second editor, not an afterthought. Make shipped a CLI for all users in April 2026 and Make Skills for AI coding assistants in May ([Make 2026 releases](https://help.make.com/2026)), n8n publishes official skills that let Claude Code and Codex build workflows ([CreateWith](https://www.createwith.com/tool/n8n/updates/n8n-ships-official-skills-for-agent-driven-workflow-creation)), and Zapier's Next Gen Zaps can be authored from Claude, ChatGPT or Cursor ([Zapier Community](https://community.zapier.com/product-updates/the-next-generation-of-zaps-is-here-53832)). Landflow's JSON workflow files are already close to a git format; with stable node IDs, sorted keys and credentials referenced by name, git sync becomes cheap enough to pull from Wave 4 into Wave 2.

## MCP, RAG, streaming chat and evals are the AI table stakes

**MCP should move from Wave 3 into the second half of Wave 2**, because it is the most widely shipped AI feature in the research. Zapier includes MCP in its Free, Pro and Team plans ([Zapier Help](https://help.zapier.com/hc/en-us/articles/39645433045773-Zapier-plan-updates-Tables-Interfaces-and-MCP-now-included)); Make has an MCP server, client and toolboxes ([Make Waves '25](https://www.make.com/blog/waves-make-product-releases-2025); [Make 2026 releases](https://help.make.com/2026)); n8n has had an MCP Server Trigger and Client Tool since 1.88 in April 2025 and made instance-level MCP generally available in 2.31 ([n8n 1.x notes](https://docs.n8n.io/release-notes/1-x/); [n8n release notes](https://docs.n8n.io/release-notes/)); Activepieces includes its MCP piece on every plan, self-hosted included ([Activepieces](https://www.activepieces.com/pieces/mcp)); Kestra 2.0 ships an MCP Tool Trigger in open source ([Kestra 2.0](https://kestra.io/blogs/release-2-0)); Windmill serves the 2026-07-28 MCP spec ([Windmill v1.781.0](https://newreleases.io/project/github/windmill-labs/windmill/release/v1.781.0)); and Dify and Langflow publish apps and projects as MCP servers ([Dify](https://docs.dify.ai/en/use-dify/publish/README); [Langflow](https://docs.langflow.org/mcp-client)). It is also cheap once Wave 1 lands. Make treats a subscenario, its inputs and its MCP exposure as one idea, a scenario as a callable function ([Make Waves '25](https://www.make.com/blog/waves-make-product-releases-2025)), and Landflow already has the equivalent: its When Called by an Agent trigger turns typed arguments into a tool's JSON schema, and Wave 1's Execute Workflow extends that to workflows. An MCP Server Trigger reuses that schema, and an MCP Client Tool lets agents use any external MCP server—the cheapest answer to the small catalogue. MCP should follow sign-in rather than precede it, since exposing workflows to outside clients requires authentication; n8n added an OAuth2 option to its MCP Server Trigger in 2.27 ([n8n release notes](https://docs.n8n.io/release-notes/)).

Wave 3's RAG plan—in-memory and SQLite vector stores, Ollama embeddings, a document loader, a text splitter and a retriever usable as an agent tool—matches the market minimum, and SQLite is a sound default: Langflow replaced its local Chroma knowledge bases with SQLite in 1.13 in October 2026 ([Langflow releases](https://github.com/langflow-ai/langflow/releases)). Two additions matter. Hybrid vector-plus-keyword search with an optional reranker is standard in Dify's Knowledge Pipeline and Gumloop's Brain ([Dify](https://dify.ai/blog/introducing-knowledge-pipeline); [Gumloop](https://docs.gumloop.com/llms.txt)). And a managed knowledge base attachable to standalone Agents delivers the "connect your sources and it works" model business users get from Gumloop, Relevance and Zapier; n8n's Agents already have one ([n8n Agents docs](https://docs.n8n.io/build/build-and-manage-agents)), and Landflow's agent docs list none. RAG depends on Wave 2's binary data for its loaders.

Streaming replies plus a hosted chat page and embeddable widget is how Dify-class products ship support bots—Dify publishes every app at once as a web app, an API, an embed and an MCP server ([Dify](https://docs.dify.ai/en/use-dify/publish/README))—so the widget stays in Wave 3 while the chat hub n8n is retiring stays off the list. Guardrails are cheap: n8n's Guardrails node checks PII, jailbreaks, NSFW content, secret keys, URLs, topical alignment, regex, keywords and custom LLM rules, and Zapier's AI Guardrails detect 30+ PII types ([n8n Guardrails](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-langchain.guardrails/); [Zapier](https://zapier.com/blog/february-2026-product-updates/)); the deterministic checks need no model, and the rest can run on local Ollama. **Cost controls deserve more priority than the roadmap gives them.** "Retrieve LLM token usage in AI Agents" has 50 replies on n8n's forum ([n8n feature requests](https://community.n8n.io/c/feature-requests/5?order=votes)), n8n added agent usage and budget settings in 2.43 ([n8n release notes](https://docs.n8n.io/release-notes/)), Zapier pauses AI runs for review at 75 tasks by default ([Zapier Help](https://help.zapier.com/hc/en-us/articles/47402591569805-Migrating-from-Agents-to-AI-by-Zapier)), and Make reviewers complain that accidental infinite loops drain credits ([G2](https://www.g2.com/products/integromat-by-celonis-make/reviews?qs=pros-and-cons)). Landflow's agents have a per-session token budget but, per their own docs, no monthly cap or model routing, so Wave 3's per-execution token and cost tracking should extend to monthly caps per agent and per workflow, plus model fallbacks.

Evals come in two forms, and Landflow needs both: n8n-style offline runs over a dataset scored by metrics for workflows ([n8n Evaluations](https://docs.n8n.io/advanced-ai/evaluations/overview/)), and Gumloop-style online grading, where an LLM judges every finished agent conversation against yes/no criteria and alerts on failure ([Gumloop Evaluations](https://docs.gumloop.com/core-concepts/evaluations.md)). Relevance and Gumloop gate parts of their evals to Enterprise ([Relevance changelog](https://relevanceai.com/docs/changelog)), a sign vendors treat evals as an upsell. **Agent channels are missing from the roadmap entirely.** n8n's Agents work in Slack, Telegram and Linear ([n8n Agents docs](https://docs.n8n.io/build/build-and-manage-agents)), Gumloop and Relevance deploy into Slack and Teams ([Gumloop](https://docs.gumloop.com/llms.txt); [Relevance changelog](https://relevanceai.com/docs/changelog)), and Relevance (January 2026) and n8n (2.35) let users approve tool calls from inside Slack ([n8n release notes](https://docs.n8n.io/release-notes/)). Landflow has only Telegram, so a Slack channel with approval buttons belongs in Wave 3. Browser use (which n8n opened to all users in 2.43), agent code sandboxes (Dify uses E2B ([Dify releases](https://github.com/langgenius/dify/releases))), voice and standalone prompt management can wait; Vellum's retreat from prompt tooling suggests versioned agent publishing covers most of that need.

## Governance can wait, except OIDC, git sync and audit events

Wave 4 is rightly last, because the market charges for it everywhere. n8n's Community Edition excludes projects, sharing, SSO, git, environments, external secrets, log streaming and multi-main HA ([n8n Community Edition](https://docs.n8n.io/hosting/community-edition-features/)); Zapier puts SAML on Team but SCIM on Enterprise ([Zapier pricing](https://zapier.com/pricing)); Make keeps custom roles (added in August 2026) and audit logs for Enterprise ([Make governance](https://www.make.com/en/blog/governance-in-make); [Make audit logs](https://help.make.com/audit-logs)); and Windmill charges for audit logs while Kestra charges for SSO, RBAC and audit logs ([Windmill pricing](https://www.windmill.dev/pricing); [Kestra pricing](https://kestra.io/pricing)). That pattern gives Landflow a choice. n8n draws its paywall at multi-user governance, and its self-hosted users complain most about missing git, SSO, sharing, variables and project folders ([Latenode community](https://community.latenode.com/t/self-hosted-n8n-which-key-functionalities-are-missing-in-the-community-version/6189)). Giving away OIDC (Wave 2), variables and version diff (Wave 1) and git sync (moved into Wave 2) costs little and markets as **"n8n Business features, free"**. SCIM, custom roles, long audit retention, external secrets and high availability are where every vendor makes its money, and they belong in a paid tier if Landflow is ever sold commercially.

Two Wave 4 items need design decisions much earlier. Queue mode depends on the Wave 1.5 database and Wave 2's object-storage binary data, since n8n's queue mode needs Postgres, Redis, a shared encryption key and S3 ([n8n queue mode](https://docs.n8n.io/hosting/scaling/queue-mode/)). Audit logging costs almost nothing later if Wave 2's sign-in emits audit events through the existing OTLP log pipeline from day one; n8n streams to syslog, webhooks and Sentry, and Zapier to Datadog and Splunk ([n8n log streaming](https://docs.n8n.io/log-streaming/); [Zapier pricing](https://zapier.com/pricing)), all reachable from an OpenTelemetry collector. External secrets should then reuse whatever project scoping RBAC introduces, as n8n's project-scoped vaults do across six providers ([n8n external secrets](https://docs.n8n.io/external-secrets/)).

A few enterprise features are weak across the market and worth building to stand out. Only Power Platform's advanced connector policies govern MCP servers alongside connectors ([Power Platform data policies](https://learn.microsoft.com/en-us/power-platform/admin/wp-data-loss-prevention)), so a node and MCP allowlist would be rare. Four-eyes approval before publishing appears, among the platforms reviewed, only in Power Platform's delegated deployments ([Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines)), and n8n transfers workflow ownership only when deleting a user ([n8n sharing](https://docs.n8n.io/workflows/sharing/)). Execution-data redaction, an n8n Enterprise feature since 2.26 ([n8n redaction](https://docs.n8n.io/workflows/executions/execution-data-redaction/)), can start in Landflow as a per-workflow "don't save payloads" switch. RPA and process mining stay out of scope—Power Automate's process-mining add-on alone costs **$5,000 per tenant per month** ([Power Automate pricing](https://www.microsoft.com/en-us/power-platform/products/power-automate/pricing))—as do a low-code app builder, which Windmill has marked legacy in its own product ([Windmill](https://www.windmill.dev/docs/core_concepts)), embedding and white-labelling, and Make Grid-style maps of the whole automation estate.

## A revised build order adds a durability wave and pulls MCP forward

The order below keeps the roadmap's waves but inserts a durability wave (1.5), moves MCP, git sync, per-workflow concurrency and automatic retry earlier, splits Wave 2 so sign-in lands before anything faces outside clients, and adds items the roadmap lacks (marked *new*).

| Phase | Build | Why at this point |
|---|---|---|
| **Wave 1** (in progress) | As planned, plus: record `versionId` on every execution; never prune waiting runs; mark waiting runs so they can release concurrency slots later; match n8n's paused sub-workflow output; canvas undo/redo (*new*) | Closes the first tier of n8n parity; the additions are cheap now and expensive to retrofit |
| **Wave 1.5** (*new*) | SQLite store with a Postgres option; per-node checkpoints and crash resume; trigger idempotency keys and per-step keys sent to plugins; per-workflow concurrency and singleton; automatic retry with backoff (from Wave 4); per-node timeouts and stop-all | Wave 1 makes the store the system of record for waits and approvals; flow control answers top open n8n requests |
| **Wave 2a** | Owner setup, users, roles, invites; scoped API keys; free OIDC; edit lock (*new*); out-of-process sandboxed Code node with Python; OAuth2 Connect buttons; binary data on filesystem or S3 | The minimum for any network-reachable install |
| **Wave 2b** | Draft/publish on pinned versions; app webhook triggers with signature checks; inbound-email trigger (*new*); CLI with stable JSON and git sync (from Wave 4); MCP Server Trigger and MCP Client Tool, plus an instance-level MCP server or skills for coding agents (from Wave 3) | Safe deploys; once sign-in exists, external agents can drive Landflow |
| **Wave 3** | RAG with hybrid search, a reranker and agent knowledge bases; streamed replies, hosted chat page and widget; Guardrails node; token and cost tracking with per-agent and per-workflow caps and model fallbacks; offline evals and online grading of agent conversations; Slack agent channel with approval buttons (*new*); files and images as LLM inputs; debounce, batching and rate limits; Flowise importer (*new*) | The AI features competitors already ship; needs Wave 2's binary data and MCP |
| **Wave 4** | Queue mode, workers and HA; audit log and SIEM streaming over OTLP; external secrets; environments and promotion; projects, sharing, SAML and SCIM; templates library; canvas groups; node and MCP allowlist (*new*); four-eyes publish and ownership transfer (*new*) | Paid tier at every competitor; needs the database, object-storage binary data and identity |
| **Later, or never** | Later: browser use, agent code sandbox, voice, AI-proposed fixes saved as new versions, automation maps, prompt management. Never: RPA, process mining, app builder, chat hub, embedding | Low demand from Landflow's audience, or competitors are retreating from them |

These priorities rest on what competitors ship and how they package it, not on usage data. n8n's forum requests were ranked by replies because vote counts were not visible, Reddit could not be fetched, Next Gen Zaps and Make's October 2026 version control are too new for their details to be known, and Workato appears only in the governance research while IFTTT was not covered at all.

## Conclusion

The competition moved off the canvas in 2026. Zapier spent the year catching up to graph semantics n8n has had for years, while the real investment went into two other questions: whether runs survive a crash, a deploy or a week-long wait, and whether an external agent can build, call and fix workflows without anyone opening the editor. Flowise's team cited exactly that second shift when it shut down, and Make, n8n and Zapier now all let coding agents author workflows. For Landflow, that makes the API, CLI and MCP surface as important as the canvas, and its JSON-native storage, polyglot plugins and local models position it well—provided the runtime underneath is durable first. Shipping RAG and agent channels on a single process writing JSON files would put approvals and long-running agent work on a store that loses them in a crash.

The packaging opening is just as concrete. n8n draws its free/paid line at multi-user governance, and much of what it charges for—version diff, variables, the insights dashboard, OIDC and git sync—costs Landflow little to give away, while per-workflow concurrency is something n8n does not offer at any tier. "Self-hosted, single binary, with n8n's Business features included" is a position n8n's own packaging and its move to Docker-only installs leave open. The integration gap is the one problem features cannot close, which is why the MCP client and the n8n importer pay back more than any single new node.
