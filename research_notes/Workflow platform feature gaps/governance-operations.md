# Governance, security, collaboration and operations features in workflow automation platforms (state as of Oct 2026), and Landflow's gaps

Scope: n8n (Business/Enterprise), Zapier (Team/Enterprise), Make (Teams/Enterprise), Workato, Tray.ai, Power Automate / Power Platform, Windmill, Kestra. Notes are organised by feature area. The last section compares the market with Landflow's current inventory, which comes from the research brief, not from a URL.

Date conventions: "n8n 2.x" version numbers below come from current n8n docs (for example, 2.10, 2.11, 2.13, 2.26 and 2.34 are cited). Items flagged **[old]** come from pages whose metadata suggests they are more than a year old. Items flagged **[deprecated]** are deprecated by the vendor.

---

## 1. Identity and access: SSO (SAML/OIDC), SCIM, RBAC, credential sharing, API keys and scopes

### Takeaway
SAML/OIDC SSO plus role-based access with at least admin, editor and viewer roles per project or workspace is table stakes for any paid team tier. SCIM, custom roles, IdP group-to-role mapping and scoped API keys are enterprise-tier differentiators. In self-hosted open-source tiers, vendors gate identity features hard: Kestra OSS has a single basic-auth account, n8n Community has no SSO or projects, and Windmill CE is the outlier with SSO for up to 10 users.

### Cited Findings

**SSO**
- n8n: SAML SSO is "Available on Business and Enterprise plans" and needs an instance owner or admin to configure — [n8n SAML](https://docs.n8n.io/user-management/saml/). OIDC is "Available on Enterprise plans" — [n8n OIDC](https://docs.n8n.io/user-management/oidc/). The pricing page lists only "SSO and LDAP" on Business and Enterprise, without naming SAML or OIDC — [n8n pricing](https://n8n.io/pricing/). **Conflict:** the OIDC doc says Enterprise only, while the pricing page lists SSO on Business without naming a protocol. Most likely Business = SAML + LDAP and Enterprise = SAML + OIDC + LDAP, but this is unconfirmed.
- n8n's 2FA enforcement covers only email-and-password logins. Users who sign in through SSO (SAML or OIDC) aren't affected by it — [n8n security settings](https://docs.n8n.io/security-settings/), [n8n security policies](https://docs.n8n.io/deploy/host-n8n/configure-n8n/security/manage-security-policies). "Enforce 2FA" is Enterprise-only on the pricing table — [n8n pricing](https://n8n.io/pricing/).
- Zapier: "SAML single sign-on (SSO)" is on **Team** and Enterprise. SCIM ("User provisioning") is Enterprise only — [Zapier pricing](https://zapier.com/pricing). The Enterprise page advertises "SSO, SCIM, and domain capture" — [Zapier Enterprise](https://zapier.com/enterprise). The Admin Center, available to Team and Enterprise accounts, holds the security settings, including SSO and SCIM — [Zapier admin center](https://help.zapier.com/hc/en-us/articles/38925392216973-Review-your-account-in-the-admin-center).
- Make: Enterprise adds "company-wide single sign-on (SSO) via OAuth2 or SAML2" and role-based access controls, per Make's security page as surfaced in search — [Make security](https://www.make.com/security). The Enterprise page lists "SSO, encryption in transit and at rest" — [Make Enterprise](https://www.make.com/en/enterprise). SSO enable, update and disable events appear in Enterprise audit logs — [Make governance blog, 4 Aug 2026](https://www.make.com/en/blog/governance-in-make).
- Workato: SAML 2.0 SSO, Google and Microsoft 365 sign-in, just-in-time provisioning through SAML, 2FA (Google Authenticator, Microsoft Authenticator, Authy), 90-day password rotation, and a session timeout from 15 minutes to 14 days (7-day default) — [Workato security](https://docs.workato.com/en/security.html).
- Tray.ai: the security policy page says "2FA is mandatory for all user accounts." It mentions SSO only for Tray's internal staff systems. I found no customer SSO setup guide — [Tray security policies](https://tray.ai/documentation/platform/enterprise-core/security-compliance/security-policies). In the separate "Helix" docs, org admins "can configure SSO" — [Tray Helix projects and workspaces](https://helix.tray.ai/documentation/concepts/projects-and-workspaces/).
- Windmill: CE allows "10 users with SSO" and a 50-user maximum. EE has uncapped SSO, and SAML and SCIM are EE only — [Windmill pricing](https://www.windmill.dev/pricing).
- Kestra: OSS "supports a single Basic Authentication account", with one shared username and password for everyone. Enterprise adds SSO via OIDC or LDAP, invitations and SCIM directory sync — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid), [Kestra pricing](https://kestra.io/pricing). Kestra Cloud uses "Built-in Google, Microsoft, or Basic Authentication" — [Kestra Enterprise docs](https://kestra.io/docs/enterprise).
- Power Automate: identity is Microsoft Entra ID, and Managed Environments add "Conditional access on individual apps" and "IP cookie binding" — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview).

**SCIM / provisioning**
- Zapier: SCIM is Enterprise only — [Zapier pricing](https://zapier.com/pricing). In the Enterprise org/workspace model, workspace access is granted through **User Groups** mapped to a workspace with an admin or member role, and "Being a member of the organization is not enough on its own" (article updated 30 Jun 2026) — [Zapier org/workspace roles](https://help.zapier.com/hc/en-us/articles/47031545308557-Roles-and-permissions-in-organizations-and-workspaces).
- Workato: SCIM handles user lifecycle (create, update, deactivate). Roles and collaborator groups are assigned through SAML attribute mappings and group claims by default. Okta can also push environment roles over SCIM with the `urn:ietf:params:scim:schemas:workato:1.0:WorkatoRole` namespace. SCIM-provisioned users get no roles until their first SAML login — [Workato SCIM (Okta)](https://docs.workato.com/scim-okta.html), [Workato SCIM (Entra ID)](https://docs.workato.com/scim-azure-ad.html), [Workato SCIM](https://docs.workato.com/scim-workato.html). Some of these pages are up to about 2 years old **[old]**.
- Windmill: SCIM is EE only — [Windmill pricing](https://www.windmill.dev/pricing). Kestra: SCIM is Enterprise — [Kestra pricing](https://kestra.io/pricing).
- n8n: neither the SAML nor the OIDC doc mentions SCIM — [n8n SAML](https://docs.n8n.io/user-management/saml/). n8n has "role mapping" audit events — [n8n log streaming](https://docs.n8n.io/log-streaming/).

**RBAC**
- n8n project roles: **Project Admin** manages members and settings and has full workflow, credential and execution access. **Project Editor** has CRUD on workflows, credentials and executions (Cloud Pro, self-hosted Enterprise per the role page). **Project Viewer** is read-only and can't execute (Enterprise). Variables and tags are global, not project-scoped — [n8n role types](https://docs.n8n.io/user-management/rbac/role-types/). Shared projects per plan: Starter 1, Pro 3, Business 6, Enterprise unlimited. "Custom roles" are Enterprise only — [n8n pricing](https://n8n.io/pricing/). **Conflict:** the role page says Project Editor is "self-hosted Enterprise", but the pricing page doesn't state Business's role set.
- Zapier Enterprise: org roles Owner and Super Admin (Super Admin has everything except billing changes), workspace roles Admin and Member. Owners and Super Admins see all workspaces, folders and Zaps, plus the audit log and log streams. Workspace Admins manage app restrictions and can view or delete all app connections — [Zapier org/workspace roles](https://help.zapier.com/hc/en-us/articles/47031545308557-Roles-and-permissions-in-organizations-and-workspaces). Team tier includes "Folder permissions", "Shared app connections" and "Owner access". Enterprise adds "Super Admin" and "Advanced admin permissions" — [Zapier pricing](https://zapier.com/pricing). The Enterprise page says access can be scoped "by team, app, action, and data" — [Zapier Enterprise](https://zapier.com/enterprise).
- Make: team roles are **Team Admin** (full access, including members, audit logs and custom functions), **Team Member** (full access to team resources, no member or settings management), **Team Operator** (read-only, but can activate, deactivate and schedule scenarios) and **Team Monitoring** (read-only on scenarios, execution logs, templates and usage). "Team Restricted Member" is a legacy role **[deprecated]**. Org Owners and Admins get implicit Team Admin in all standard teams — [Make Teams](https://help.make.com/teams). Team Members can no longer rename teams from 2 Aug 2026 — [Make change notice](https://help.make.com/team-edit-permission-removed-from-team-member-role). **Custom Roles**, assignable at the organization or team level, are Enterprise only (announced 4 Aug 2026) — [Make governance blog](https://www.make.com/en/blog/governance-in-make).
- Workato: two layers. Environment roles govern projects, tools and admin settings, and project roles govern actions inside a project. Custom roles can be limited to specific folders, recipes and connections, and workspaces isolate teams — [Workato security](https://docs.workato.com/en/security.html). Collaborator groups grant project access only, not environment roles — [Workato SCIM (Entra ID)](https://docs.workato.com/scim-azure-ad.html).
- Tray.ai: org roles Owner (one per org), Admin, Contributor and Viewer. Workspace roles can be higher than the org role, and Viewers can't replay executions. A deleted user's personal-workspace assets move to a new shared workspace named after the user — [Tray roles](https://tray.ai/documentation/platform/enterprise-core/organisation-management/users/roles). The Helix docs describe a different model (workspace admin, editor and reader), where isolating a sensitive project means giving it its own workspace — [Tray Helix](https://helix.tray.ai/documentation/concepts/projects-and-workspaces/). **Conflict:** the two Tray doc sets describe different role models.
- Windmill: CE has max 4 groups and "Override default roles only". EE has unlimited groups, custom workspace roles and workspace service accounts — [Windmill pricing](https://www.windmill.dev/pricing).
- Kestra Enterprise: resource-and-action permissions (for example `FLOW: EXECUTE`), assignable per namespace to users, groups and service accounts — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid), [Kestra pricing](https://kestra.io/pricing).
- Power Automate: Managed Environments add "Limit sharing" — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview). Pipelines use a "Deployment Pipeline Administrator" security role — [Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines).

**Credential sharing**
- n8n: credential sharing is on every paid tier (Starter, Pro, Enterprise) — [n8n pricing](https://n8n.io/pricing/). Workflow editors can *use* credentials in a shared workflow without having them shared directly, but can't edit nodes that use credentials not shared with them — [n8n sharing](https://docs.n8n.io/workflows/sharing/). Project Admins can create "end-user credentials" — [n8n role types](https://docs.n8n.io/user-management/rbac/role-types/).
- Zapier: "Shared app connections" on Team and Enterprise. Enterprise adds "Managed app connections", meaning company-owned connections maintained by IT — [Zapier pricing](https://zapier.com/pricing), [Zapier Enterprise](https://zapier.com/enterprise). Enterprise "allowed domains for app connections" restricts new OAuth connections to listed domains. It doesn't affect existing connections, API-key apps, or API by Zapier — [Zapier allowed domains](https://help.zapier.com/hc/en-us/articles/43996004782349-Allowed-domains-for-app-connections).
- Make: "Credential Requests" collect third-party credentials securely. On every plan, real-time email alerts notify a connection's owner when someone else uses it, and that usage is logged in Enterprise audit logs — [Make governance blog](https://www.make.com/en/blog/governance-in-make), [Make audit logs](https://help.make.com/audit-logs).

**API keys and scopes**
- n8n: API keys are sent in the `X-N8N-API-KEY` header and can have an expiration. Scopes are Enterprise only, and "Non-Enterprise API keys have full access to all the account's resources and capabilities." The API isn't available during the free trial — [n8n API auth](https://docs.n8n.io/api/authentication/).
- Kestra Enterprise: "service accounts, API tokens, OAuth2, and JWT" — [Kestra pricing](https://kestra.io/pricing). Windmill EE: workspace service accounts. Windmill also sends critical alerts on API token expiry — [Windmill pricing](https://www.windmill.dev/pricing), [Windmill critical alerts](https://www.windmill.dev/docs/core_concepts/critical_alerts).
- Tray.ai has a "Self-serve API Tokens" feature page, which I didn't fetch — [Tray API tokens](https://tray.ai/documentation/releases/features/self-serve-api-tokens). Each Tray Embedded environment has its own API token — [Tray environment setup](https://tray.ai/documentation/tray-uac/development-and-testing/environment-promotion/setting-up-your-environment).

### Inferences
- **Table stakes (team tier):** individual user accounts, invitations, admin/editor/viewer roles, project- or workspace-scoped access, shared credentials, SAML SSO (Zapier puts it on Team), and personal API keys.
- **Differentiators (enterprise tier):** SCIM, OIDC plus IdP group-to-role mapping, custom roles, read-only viewer role, enforced 2FA, scoped or expiring API keys, service accounts, managed (IT-owned) connections, and domain restrictions on OAuth connections.
- **What self-hosters get free:** at minimum a login. Kestra OSS has basic auth and Windmill CE has up to 50 users with 10 SSO users. Fine-grained RBAC and SCIM are almost always paid. Running with no auth at all is below the market floor for anything reachable beyond localhost.

### Gaps
- n8n Community Edition's exact user-account model (owner plus members, with no sharing or projects) isn't confirmed beyond the Community Edition exclusion list — [n8n CE features](https://docs.n8n.io/hosting/community-edition-features/).
- I found no Make help page that confirms SCIM support. The Make pages I fetched don't mention SCIM.
- I found no Tray.ai customer SSO or SCIM setup doc in the classic docs.
- Power Platform security-role details (Environment Admin, Environment Maker and so on) weren't fetched.

## 2. Collaboration: projects/workspaces, folders, tags, comments, sharing, concurrent editing, ownership transfer, template libraries

### Takeaway
The market's basic collaboration unit is a shared project or workspace with folders and role-based membership. Sharing individual workflows is common, and true real-time co-editing is rare: n8n uses a single-editor lock and Windmill sells multiplayer as EE. Private, governed template catalogs ("approved templates", "custom blueprints", "private hub") are an enterprise differentiator.

### Cited Findings
- n8n: shared projects are tiered (1 / 3 / 6 / unlimited). Folders appear only as a free-trial feature on the pricing page — [n8n pricing](https://n8n.io/pricing/). Self-hosted Community Edition unlocks **folders** with free registration, but excludes Projects and Sharing — [n8n CE features](https://docs.n8n.io/hosting/community-edition-features/).
- n8n workflow sharing is on Cloud (all plans) and self-hosted Business and Enterprise. Workflow roles are creator and editor, and editors can't share or delete. "You can't change the workflow owner, except when deleting the user." Instance owners and admins can view and share all workflows — [n8n sharing](https://docs.n8n.io/workflows/sharing/).
- n8n concurrent editing: "Only one person can edit a workflow at a time. Other users see it in read-only mode." The lock releases when the editor stops or goes idle. In n8n 2.0, autosaved edits stay in draft until published — [n8n publishing FAQ](https://support.n8n.io/article/understanding-workflow-publishing-in-n-8-n-2-0), [n8n save and publish](https://docs.n8n.io/workflows/publish/).
- Zapier Team: "Shared workspace", "Folder permissions", "Shared app connections" and up to 25 seats. Enterprise: unlimited users and "Workspaces" — [Zapier pricing](https://zapier.com/pricing). In Enterprise, **Teams** are set by Workspace Admins and used for sharing folders and connections and for mentions, while **User Groups** are set at the org level — [Zapier org/workspace roles](https://help.zapier.com/hc/en-us/articles/47031545308557-Roles-and-permissions-in-organizations-and-workspaces). Enterprise also offers "Guided templates" (builds start from approved templates) and auto-generated "Canvas documentation" — [Zapier Enterprise](https://zapier.com/enterprise). Zapier has a Team/Enterprise article on importing and exporting Zaps — [Zapier import/export](https://help.zapier.com/hc/en-us/articles/8496308481933-Import-and-export-Zaps-in-your-Team-or-Enterprise-account), title only, not fetched.
- Make: organizations contain teams — [Make organizations and teams](https://help.make.com/organizations-and-teams). **Private Spaces** give each member an isolated workspace that is "hidden from the rest of the org by default" on every plan, including Free. Read-only admin visibility into Private Spaces is Enterprise only (4 Aug 2026) — [Make governance blog](https://www.make.com/en/blog/governance-in-make). Enterprise lists "Scenario tagging" under advanced governance and offers ownership visibility: "Know what's running, who built it, and who can change it" — [Make Enterprise](https://www.make.com/en/enterprise).
- Workato: workspaces isolate users and resources by team or function, and custom roles can be scoped to folders, recipes and connections — [Workato security](https://docs.workato.com/en/security.html).
- Tray.ai: workspaces split an org by department or environment, and a deleted user's assets are transferred to a new shared workspace — [Tray roles](https://tray.ai/documentation/platform/enterprise-core/organisation-management/users/roles).
- Windmill EE: "Multiplayer on WebIDE" and "Private Hub". CE limits workspaces (forks count toward a 3-workspace limit) — [Windmill pricing](https://www.windmill.dev/pricing).
- Kestra Enterprise: "Custom blueprints – A private catalog of ready-to-use flows, versioned in Git", plus system announcements (in-app banner) and Apps (forms, approvals, dashboards on top of flows) — [Kestra pricing](https://kestra.io/pricing). Blueprint libraries can be version-controlled with `PushBlueprints` and `SyncBlueprints` — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid).
- Power Platform: Managed Environments include "Limit sharing", "Maker welcome content" and "Administer the catalog" — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview).

### Inferences
- **Table stakes:** shared projects or workspaces, folders, tags, per-workflow sharing, and an edit lock or conflict detection so two people don't overwrite each other.
- **Differentiators:** real-time multiplayer editing (Windmill EE), private template catalogs (Zapier, Kestra and Windmill enterprise tiers), private per-user sandboxes with admin oversight (Make), auto-generated documentation (Zapier), and governed ownership transfer.
- Ownership transfer is weak across vendors. n8n only reassigns ownership when a user is deleted, and Tray moves a deleted user's assets to a new shared workspace. This is an opportunity rather than a market expectation.

### Gaps
- I found no authoritative docs on in-canvas **comments** or annotations for any of the vendors. They may exist (for example, n8n sticky notes, Make notes or Zapier mentions), but I couldn't verify them.
- I didn't verify n8n's mechanism for moving workflows between projects; the sharing page doesn't cover it.

## 3. Lifecycle: version history and restore, environments, git source control, promotion and deployment, approvals, export/import

### Takeaway
Version history with restore is table stakes, though retention is tiered (n8n: 24 hours for everyone, 365+ days on Enterprise; Zapier: 1 / 6 / 12 months). Multi-environment promotion is an enterprise feature everywhere: Workato DEV/TEST/PROD, Power Platform Pipelines, Windmill deploy-to-prod UI, and n8n branch-per-environment git. Formal deployment approvals exist only at the top end (Power Platform delegated deployments). Git-native lifecycle is the developer-oriented norm (n8n, Windmill, Kestra, Power Platform). Workato and Tray deliberately avoid git in favour of built-in deploy and rollback.

### Cited Findings

**Version history**
- n8n: "Versions from the last 24 hours are available for all users"; five days on Cloud Pro; full history on Enterprise. Named versions (Cloud Pro and Enterprise, self-hosted Business and Enterprise) are never auto-pruned. Users can restore, clone to a new workflow, open in a new tab to compare, or download as JSON. Settings changes don't create versions — [n8n workflow history](https://docs.n8n.io/workflows/history/). Pricing table: Starter 1 day, Pro 5 days, Enterprise 365+ days. **Workflow Diff** is Enterprise — [n8n pricing](https://n8n.io/pricing/). n8n 2.0 introduced a draft/publish model — [n8n publishing FAQ](https://support.n8n.io/article/understanding-workflow-publishing-in-n-8-n-2-0).
- Zapier "Versions (rollback)": Pro 1 month, Team 6 months, Enterprise 1 year. "Compare Versions" is Enterprise only — [Zapier pricing](https://zapier.com/pricing).
- Tray.ai **Project Versioning (beta)**: point-in-time snapshots of workflows, config and solutions, each with a title, description and change record. Snapshots can be reverted or exported as JSON. Datatables, vector tables and API management aren't included. The Projects API exposes create, list and export for versions — [Tray project versioning](https://docs.tray.ai/platform/enterprise-core/lifecycle-management/project-versioning), [Tray UAC versioning](https://tray.ai/documentation/tray-uac/lifecycle-management-sdlc/managing-project-versions/project-versioning/), [Tray Projects API](https://tray.ai/documentation/developer/platform-apis/projects).
- Kestra OSS: "Draft revisions – Save work in progress without affecting the flow that triggers run" — [Kestra pricing](https://kestra.io/pricing).
- Windmill: drafts are user-scoped, autosaved, and deployed when ready (not marked EE) — [Windmill deploy to prod](https://www.windmill.dev/docs/advanced/deploy_to_prod).

**Environments and promotion**
- n8n source control and environments are on Business and Enterprise: "Linking your n8n instances to a Git repository lets you create multiple n8n environments, backed by Git branches." Instance owners and admins can push and pull, and project admins can push but not pull — [n8n source control](https://docs.n8n.io/source-control-environments/). The Enterprise pricing column says "2 instances: dev, prod" — [n8n pricing](https://n8n.io/pricing/). Pulling from git creates workflow-history versions in the DB — [n8n workflow history](https://docs.n8n.io/workflows/history/).
- Workato: three environments (DEV, TEST, PROD) are provisioned automatically, and changes are made in DEV and deployed to TEST or PROD. Deploying needs the deployment privilege in both source and target. "View a complete deployment history and roll back to a previous deployment at any time." The deploy feature needs no "JSON manifests, git, or scripting tools", and CI/CD goes through the Projects API. Environments are plan-dependent and automatic for customers since 22 Dec 2021, and each environment gets its own encryption CMK — [Workato environments](https://docs.workato.com/en/features/environments.html), [Workato EKM](https://docs.workato.com/en/security/data-protection/encryption-key-management.html). Recipes and dependencies can also be packaged by export — [Workato export](https://docs.workato.com/en/recipe-development-lifecycle/export.html), linked from the environments page.
- Power Platform Pipelines deploy solutions plus connections, connection references and environment variables, prevalidated against the target. The same artifact must pass stages in order and is tamper-protected, so it "can't bypass QA environments or your approval processes." Approvals are handled by **delegated deployments** with a service principal or pipeline owner. Every deployment stores managed and unmanaged solution backups automatically. Previous versions can be redeployed if the setting is enabled. Cross-tenant deploys aren't supported, and cross-geo deploys need a setting. Targets must be Managed Environments, and from **October 2026** admins get 30 days to approve managed-environment enablement before deployments to unmanaged targets are blocked — [Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines).
- Power Platform **Dataverse Git integration** syncs solutions with Azure DevOps or GitHub, in a human-readable per-object format. It is meant for developer environments only, with builds plus pipelines used to deploy to test and prod — [Dataverse Git integration](https://learn.microsoft.com/en-us/power-platform/alm/git-integration/overview).
- Windmill: workspace forks ("compares this to git branches") and persistent dev workspaces paired with a locked prod workspace are not marked EE. **Git sync** and **Deploy to prod using the UI** are "Cloud plans and Self-Hosted Enterprise Edition only". Git Promotion (staging workspace to prod branch PR to deploy) lets you "review all the changes on a PR before merging", and CLI `wmill sync pull/push` also exists. The navigation lists "Protection rulesets" — [Windmill deploy to prod](https://www.windmill.dev/docs/advanced/deploy_to_prod). **Conflict:** the pricing page says CE gets git sync "up to 2 users", while the deploy doc says git sync is EE or Cloud only — [Windmill pricing](https://www.windmill.dev/pricing).
- Kestra: the pricing page lists Git integration under "Both versions include" — [Kestra pricing](https://kestra.io/pricing). The OSS-vs-paid page describes OSS migration only as "exporting and importing flow YAML" — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid). **Conflict:** these two pages disagree on whether OSS has git integration. Multi-tenancy ("Isolate teams or environments inside one Kestra instance") is Enterprise — [Kestra pricing](https://kestra.io/pricing).
- Tray.ai: for Embedded, the recommended pattern is a separate Tray org per environment (dev, staging, prod), with custom services and connectors recreated in each — [Tray environment setup](https://tray.ai/documentation/tray-uac/development-and-testing/environment-promotion/setting-up-your-environment). Classic docs suggest workspaces per environment (dev, prod) — [Tray roles](https://tray.ai/documentation/platform/enterprise-core/organisation-management/users/roles).
- Make Enterprise: "Role-based access controls who builds and changes what" — [Make Enterprise](https://www.make.com/en/enterprise). I found no Make environments or promotion feature.

**Variables (as an environment enabler)**
- n8n "Global variables" are on Pro and Enterprise — [n8n pricing](https://n8n.io/pricing/). Custom variables are excluded from Community Edition — [n8n CE features](https://docs.n8n.io/hosting/community-edition-features/). Variables are instance-global, not project-scoped — [n8n role types](https://docs.n8n.io/user-management/rbac/role-types/).
- Make has team and organization variables, and changes to them are audited (Enterprise) — [Make audit logs](https://help.make.com/audit-logs), [Make custom variables](https://help.make.com/custom-variables).
- Power Platform pipelines provide environment variables at deploy time — [Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines).

### Inferences
- **Table stakes:** automatic version history with restore, JSON export and import of individual workflows, and draft-vs-published separation. n8n 2.0, Windmill drafts and Kestra draft revisions all show that editing a live workflow in place is now considered unsafe.
- **Differentiators:** long or unlimited history, named versions, visual diff (n8n and Zapier gate it to Enterprise), environments with promotion, git sync, deployment history with rollback, approvals or gated deployments, and per-environment variables and connection rebinding.
- For a developer-leaning, self-hosted product, git-backed workflows are the most natural lifecycle path. Kestra (YAML), Windmill (CLI sync) and n8n (branch-per-env) all lean this way. Landflow's JSON-file storage is unusually well suited to this because the on-disk format can already be the git format.

### Gaps
- I didn't fetch n8n's subpages on what exactly is pushed or pulled (credential stubs, variables, tags, folders, projects).
- I found no first-party evidence of change-approval workflows (four-eyes review before publish) in n8n, Zapier or Make. Power Platform has delegated deployments, and Windmill relies on git PR review.

## 4. Security: external secrets, encryption at rest, IP allowlists, network isolation, sandboxed code, DLP/connector policies, audit logs, SIEM log streaming

### Takeaway
Encryption at rest and a credential vault are universal. Audit logs (6–12 months retention), log streaming to SIEM (Datadog, Splunk, syslog, webhook) and external secrets managers (Vault, AWS, GCP, Azure, often 1Password or Infisical) are near-universal *enterprise* features and almost never free. Connector or action allowlists (DLP) and customer-managed keys (BYOK) are the top-tier differentiators: Power Platform is the most advanced, and Zapier and Workato follow. Sandboxed code execution is a self-hosted concern, addressed by Windmill (nsjail, PID namespaces) and n8n (task runners).

### Cited Findings

**External secrets**
- n8n: 1Password (Connect Server), AWS Secrets Manager, Azure Key Vault, GCP Secrets Manager, HashiCorp Vault and Infisical. HashiCorp Vault Secrets is *not* supported. Enterprise only, on Cloud and self-hosted. Secrets are referenced as `{{ $secrets.<vault-name>.<secret-name> }}`, and only in credential fields. Multiple vaults per provider from 2.10.0. Vaults can be scoped to a project from 2.11.0, and once a vault is assigned to a project, only that project's credentials can use it. Project roles can use vault secrets from 2.13.0 if the admin enables it — [n8n external secrets](https://docs.n8n.io/external-secrets/), [n8n role types](https://docs.n8n.io/user-management/rbac/role-types/).
- Windmill: "Custom secret encryption" is in both CE and EE. External secret backends (Vault, Azure Key Vault, AWS Secrets Manager) are EE only — [Windmill pricing](https://www.windmill.dev/pricing).
- Kestra: OSS secrets are supplied as environment variables. Enterprise adds namespace-level secrets, read-only secrets, Azure Key Vault and HashiCorp Vault, and per-tenant secret managers — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid). The pricing page says secrets can be read "from Vault, AWS, Azure, Google Cloud, and other backends" — [Kestra pricing](https://kestra.io/pricing).
- Make: "Credential Requests" collect credentials, and "keys" are an audited object type — [Make governance blog](https://www.make.com/en/blog/governance-in-make), [Make audit logs](https://help.make.com/audit-logs). I found no Make external-vault integration.

**Encryption at rest and keys**
- Workato: AES-256 at rest and in transit. Job history is double-encrypted with a global cloud key plus a tenant key. The key hierarchy runs from a Customer Main Key to hourly keys to data keys, and keys are unique per workspace. The CMK can be Workato-managed (rotated at least yearly) or customer-managed (BYOK, replaceable once per 24 hours). Data tables and Workflow apps data use filesystem encryption only. EKM is "included in specific pricing plans" — [Workato security](https://docs.workato.com/en/security.html), [Workato EKM](https://docs.workato.com/en/security/data-protection/encryption-key-management.html).
- Power Platform Managed Environments: Customer Managed Key (CMK), Lockbox, IP Firewall, IP cookie binding, Virtual Network support and masking rules — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview).
- Tray.ai: encrypted at rest, with an extra layer for workflow authentications. Three data-residency regions: US (default), EU (Ireland) and APAC (Sydney). SOC 1 Type 2, SOC 2 Type 2 and HIPAA — [Tray security policies](https://tray.ai/documentation/platform/enterprise-core/security-compliance/security-policies).
- Make: encryption in transit and at rest, GDPR, SOC 2 Type II, SOC 3 and ISO 27001 — [Make Enterprise](https://www.make.com/en/enterprise). Enterprise runs in "a separate Celonis Amazon Web Service environment" on a dedicated server in your region — [Make upgrade to Enterprise](https://help.make.com/upgrade-to-enterprise).
- Zapier: SOC 2 Type II, SOC 3, GDPR and CCPA — [Zapier Enterprise](https://zapier.com/enterprise).

**Network**
- Zapier: "Static IP (dedicated IPs for firewall whitelisting)" is on Pro, Team and Enterprise. Enterprise adds VPC Peering to internal data sources — [Zapier pricing](https://zapier.com/pricing), [Zapier Enterprise](https://zapier.com/enterprise).
- Workato: IP allowlists, plus an on-prem agent (OPA) that reaches on-prem apps, databases and folders — [Workato security](https://docs.workato.com/en/security.html).
- Kestra Enterprise: private networking. Kestra Cloud runs on GCP in the US and EU (Belgium) — [Kestra Enterprise docs](https://kestra.io/docs/enterprise).
- Tray.ai publishes source IPs to allowlist for log streaming — [Tray log streaming](https://tray.ai/documentation/platform/enterprise-core/logs-debugging/log-streaming).

**Sandboxed code execution**
- Windmill: PID-namespace isolation (`ENABLE_UNSHARE_PID=true`, off by default, Linux only) and NSJAIL sandboxing (filesystem, network and resource limits, unprivileged users, off by default). Per-script `sandbox` and `no_network` annotations. Dedicated and agent workers have no DB access and talk only through the API. Agent and dedicated workers appear under the "Enterprise Features" navigation section — [Windmill security isolation](https://www.windmill.dev/docs/advanced/security_isolation). Script-specific workers are EE — [Windmill pricing](https://www.windmill.dev/pricing).
- n8n: task runners exist. "Runner" events (task requested, response received) are streamable — [n8n log streaming](https://docs.n8n.io/log-streaming/). I didn't fetch n8n's task-runner sandbox doc.

**DLP and connector policies**
- Power Platform **data policies** (formerly "DLP policies"; page dated 14 Oct 2026) control access to whole connectors or specific actions, at design time and runtime. On a policy change, violating apps, flows and agents are suspended or quarantined and connections are disabled. Full enforcement can take up to 24 hours (usually within an hour). **Advanced connector policies (ACP)** govern certified connectors and **MCP connectors and their MCP servers**. ACP doesn't support virtual connectors, and Copilot Studio virtual connectors are moving to dedicated rules — [Power Platform data policies](https://learn.microsoft.com/en-us/power-platform/admin/wp-data-loss-prevention).
- Zapier Enterprise: "App access controls (approved app list)", "Action restrictions" ("Define exactly which actions are allowed in each app"), "Domain restrictions", and AI Guardrails that block sensitive data — [Zapier pricing](https://zapier.com/pricing), [Zapier Enterprise](https://zapier.com/enterprise), [Zapier AI Guardrails](https://help.zapier.com/hc/en-us/articles/43960366238221-How-to-get-started-with-AI-Guardrails-by-Zapier).
- Workato data masking: masked fields don't display in the UI and are excluded from job history and audit-log streaming — [Workato security](https://docs.workato.com/en/security.html).
- n8n **execution data redaction** (Enterprise, n8n 2.26.0+): an instance-wide minimum redaction policy that individual workflow settings can't weaken, with production-only or production-plus-manual scope. It hides payloads and error details, but not node names, status or timing. It doesn't cover Code-node `console.log`, inter-node data or webhook responses, and it doesn't change DB storage — [n8n redaction](https://docs.n8n.io/workflows/executions/execution-data-redaction/), [n8n redact execution data](https://docs.n8n.io/deploy/host-n8n/configure-n8n/security/redact-execution-data).
- Make: the "keep data confidential" scenario setting means Make won't retain that data, on any plan — [Make scenario settings](https://help.make.com/scenario-settings). Make has a "Feature controls page for toggling experimental and AI features" — [Make governance blog](https://www.make.com/en/blog/governance-in-make).
- Tray.ai redacts sensitive authentication data from workflow logs — [Tray security policies](https://tray.ai/documentation/platform/enterprise-core/security-compliance/security-policies).

**Audit logs**
- n8n: audit logging is Enterprise only — [n8n pricing](https://n8n.io/pricing/). Audit events cover logins, user and credential changes, workflow changes, variables, external secrets, role mapping, MCP activity (from 2.34.0), and packages (community nodes). `anonymizeAuditMessages` strips sensitive payload data — [n8n log streaming](https://docs.n8n.io/log-streaming/).
- Zapier: audit log 6 months on Team and 1 year on Enterprise — [Zapier pricing](https://zapier.com/pricing). Enterprise access needs super admin or owner — [Zapier audit log](https://help.zapier.com/hc/en-us/articles/13295074298125-Use-the-audit-log-to-review-your-account-activity). Enterprise "Asset History" exposes audit data through an API — [Zapier Enterprise](https://zapier.com/enterprise).
- Make: Enterprise only, with 12 months retention, at org level (owners and admins) and team level (team admins). Events cover scenarios, connections, webhooks, keys, teams, variables, data stores, functions, 2FA enforcement, credential requests, SSO, private spaces and credential usage. I found no export option — [Make audit logs](https://help.make.com/audit-logs).
- Workato: Activity audit log plus audit log streaming — [Workato security](https://docs.workato.com/en/security.html).
- Windmill: audit logs are EE only, with "Unlimited retention" — [Windmill pricing](https://www.windmill.dev/pricing). Kestra: audit logs are Enterprise and "Record every action by every user on every resource" — [Kestra pricing](https://kestra.io/pricing).
- Power Platform pipelines save customizations and an audit log automatically — [Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines).

**Log streaming and SIEM**
- n8n: Enterprise only. Destinations are syslog, generic webhook and Sentry, configurable through the `N8N_LOG_STREAMING_DESTINATIONS` env var. Event groups are workflow, node, audit, worker, AI node (for example "LLM generated" and "Tool called"), runner and queue — [n8n log streaming](https://docs.n8n.io/log-streaming/).
- Zapier: "Log Streams" on Enterprise, sending real-time workflow data to Datadog or Splunk — [Zapier pricing](https://zapier.com/pricing), [Zapier Enterprise](https://zapier.com/enterprise).
- Tray.ai: log streaming to Datadog or Kibana on the Team add-on and Enterprise. It is enabled by support ticket, and Embedded events carry solution-instance IDs — [Tray log streaming](https://tray.ai/documentation/platform/enterprise-core/logs-debugging/log-streaming).
- Kestra Enterprise "Log shippers": "Send logs and audit logs to Datadog, Splunk, Elasticsearch, your SIEM, and more" — [Kestra pricing](https://kestra.io/pricing).
- Windmill: OpenTelemetry tracing and logging, Prometheus, and queue and HTTP tracing are all EE only — [Windmill pricing](https://www.windmill.dev/pricing).
- Power Platform: "Export data to Azure Application Insights" is a Managed Environments feature — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview).

### Inferences
- **Table stakes (any tier):** encrypted credential store, secrets never shown after save, and TLS. Landflow already meets these for credentials.
- **Table stakes (enterprise tier):** audit log with 6–12+ months retention, SIEM streaming, external secrets (Vault plus the three cloud KMSs), 2FA enforcement, and static egress IPs or an allowlist (for SaaS).

- Observability export is gated in at least one competitor: Windmill sells OTel and Prometheus as EE. Landflow's free OTLP and Prometheus support is therefore a real differentiator, not just catch-up.

## 5. Operations: queue mode/workers, scaling, HA, retention and pruning, concurrency, failure alerting, insights, SLAs, backup/restore, multi-tenant and embedded

### Takeaway
For self-hosted products, the market baseline is a database-backed store (Postgres), configurable execution pruning that is on by default, a concurrency cap and an error-workflow or alert hook, and these are free in n8n. Horizontal scaling with a queue and workers is widely available. Multi-main HA, worker-management UIs, autoscaling, long insights history and embedded/white-label are paid or enterprise. ROI-style insights ("time saved", failure rate) are now a standard dashboard element, led by n8n and Make Grid.

### Cited Findings

**Queue mode, workers and HA**
- n8n queue mode: the main process sends execution IDs to Redis, and workers (`n8n worker`, `--concurrency` default 10, 5+ recommended) read from and write to the DB. Webhook processors scale behind a load balancer. "Running a distributed system with this setup over SQLite isn't supported." All instances share the encryption key. Queue mode doesn't support filesystem binary data storage, so S3 is used instead. Large webhook responses can be offloaded to S3 or Azure from 2.34.0. Workers expose `/healthz`, `/healthz/readiness` and `/metrics` — [n8n queue mode](https://docs.n8n.io/hosting/scaling/queue-mode/). The pricing page shows queue mode on Business ("Queue mode for scaling") and Enterprise — [n8n pricing](https://n8n.io/pricing/).
- n8n **multi-main HA**: a leader runs at-most-once tasks (timers, pollers, pruning) and followers take over on failure. It requires Postgres, Redis, the same version everywhere, `N8N_MULTI_MAIN_SETUP_ENABLED=true` and sticky sessions. It is self-hosted Enterprise only and "isn't available on n8n Cloud." The worker view UI is Enterprise — [n8n queue mode](https://docs.n8n.io/hosting/scaling/queue-mode/). The pricing page lists multi-main as "Coming soon" — [n8n pricing](https://n8n.io/pricing/). Multi-main is excluded from Community Edition — [n8n CE features](https://docs.n8n.io/hosting/community-edition-features/).
- Windmill EE: worker group management UI, self-hosted autoscaling, script-specific workers, concurrency limits, and Kafka, NATS, SQS, GCP and Azure triggers. CE: "Unlimited executions" — [Windmill pricing](https://www.windmill.dev/pricing).
- Kestra: OSS runs standalone or as a distributed cluster with a PostgreSQL or MySQL queue. Enterprise adds Kafka, Redis and AMQP backends, worker groups (route tasks by tag, reserve capacity), remote worker groups with autoscaling, all task runners (Kubernetes, cloud batch, VMs), and maintenance mode — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid), [Kestra pricing](https://kestra.io/pricing), [Kestra Enterprise docs](https://kestra.io/docs/enterprise).

**Retention and pruning**
- n8n self-hosted: pruning is on by default. `EXECUTIONS_DATA_MAX_AGE` defaults to 336 h (14 days) and `EXECUTIONS_DATA_PRUNE_MAX_COUNT` to 10,000, and pruning triggers when either limit is hit. A 1 h hard-delete buffer applies (soft delete, then hard delete). Running, waiting, tagged or rated executions are never pruned. Saving success, error, progress and manual executions is configurable globally and per workflow. On SQLite, space must be reclaimed with VACUUM — [n8n execution data](https://docs.n8n.io/hosting/scaling/execution-data/). Cloud tiers: execution log retention 7 days (Starter), 30 days (Pro), unlimited (Enterprise). Max saved executions 2.5K, 25K and 50K — [n8n pricing](https://n8n.io/pricing/).
- Zapier: Zap history is kept 29–69 days by default, and Zapier guarantees 60 days and shows up to 10,000 runs — [Zapier Zap history](https://help.zapier.com/hc/en-us/articles/8496291148685-View-and-manage-your-Zap-history). Enterprise "Custom data retention" is account-wide and set by admins — [Zapier pricing](https://zapier.com/pricing), [Zapier data retention](https://help.zapier.com/hc/en-us/articles/8496327478413-Customize-data-retention-in-Zapier). **Conflict:** one help article gives a 7–30 day range, while others say retention can be extended up to 90 days — [Zapier Team/Enterprise management](https://help.zapier.com/hc/en-us/articles/8496291989645-Manage-your-Zapier-Team-or-Enterprise-account).
- Workato: Standard and Business plans keep data 30 days (fixed). Enterprise keeps 90 days and can configure it from 1 hour to 90 days, at workspace level, with a per-recipe "don't store job data" option. After expiry, the job summary is kept but inputs and outputs are deleted, which disables "Repeat this job" — [Workato data retention](https://docs.workato.com/en/security/data-protection/data-retention.html). Legacy plans have different terms **[deprecated]**.
- Tray.ai: execution logs are kept 7 or 30 days depending on package, can be reduced to 24 hours or disabled, and all data is deleted 60 days after contract end — [Tray security policies](https://tray.ai/documentation/platform/enterprise-core/security-compliance/security-policies).
- Make: "By default, log data is stored for 30 days. In our Enterprise Plan, we also offer the ability to store data for an extended period" — [Make security](https://www.make.com/security).
- Power Automate: run history is shown for 28 days. For solution-aware flows, Dataverse FlowRun retention can be set to 28, 14 or 7 days, disabled, or a custom value through `FlowRunTimeToLiveInSeconds` — [Power Automate run history in Dataverse](https://learn.microsoft.com/en-us/power-automate/dataverse/cloud-flow-run-metadata), [Missing run history](https://learn.microsoft.com/en-us/troubleshoot/power-platform/power-automate/flow-run-issues/missing-runs-or-triggers-history-for-a-flow).
- Windmill: CE keeps job runs for "30 days or less", while EE retention is unlimited — [Windmill pricing](https://www.windmill.dev/pricing). Kestra: an external log data store offers "Unlimited (based on customer setup)" retention — [Kestra Enterprise docs](https://kestra.io/docs/enterprise).

**Concurrency controls**
- n8n self-hosted: `N8N_CONCURRENCY_PRODUCTION_LIMIT` is disabled by default. Over-limit production executions queue in FIFO order, and manual, sub-workflow, error and CLI executions aren't limited. There are no per-workflow limits — [n8n concurrency control](https://docs.n8n.io/hosting/scaling/concurrency-control/). Cloud tiers: 5, 20 (or 50) and 200+ concurrent executions — [n8n pricing](https://n8n.io/pricing/). **Conflict:** the Pro tier shows 20 in the table and "up to 50" in the bullets.
- Windmill concurrency limits are EE — [Windmill pricing](https://www.windmill.dev/pricing).

**Alerting on failures**
- Windmill **critical alerts** (EE) fire on job re-runs after a crash, workspace error-handler failure, worker count below a threshold, queue length over a threshold, schedule skips, API token expiry, license, and disk under 1 GB. They go to email (SMTP), Slack, Teams and the UI — [Windmill critical alerts](https://www.windmill.dev/docs/core_concepts/critical_alerts).
- Make: real-time email alerts when someone uses your connection, on all plans — [Make governance blog](https://www.make.com/en/blog/governance-in-make).
- n8n streams "workflow failed" and "queue job stalled/failed" events (Enterprise) — [n8n log streaming](https://docs.n8n.io/log-streaming/).

**Insights and analytics**
- n8n **Insights** tracks production executions, failures and failure rate, time saved, and average run time. The summary banner (last 7 days) is free on all editions. The dashboard is on Cloud Pro and Enterprise and self-hosted Business and Enterprise. Ranges: Business 24 h to 30 days; Enterprise up to 1 year with hourly, daily and weekly granularity. Time saved can be fixed per workflow or dynamic through "Time Saved" nodes (per execution or per item), and error-workflow runs are excluded (2.23.0+). `N8N_INSIGHTS_MAX_AGE_DAYS` defaults to 365, max 730 — [n8n Insights](https://docs.n8n.io/insights/), [n8n pricing](https://n8n.io/pricing/).
- Zapier Enterprise: "Analytics" and an "Observability API" — [Zapier pricing](https://zapier.com/pricing).
- Make Enterprise: **Make Grid** ("See every automation and agent in one live view") and real-time analytics — [Make Enterprise](https://www.make.com/en/enterprise).
- Power Platform: weekly usage insights in Managed Environments, and Power BI pipeline analytics — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview), [Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines). Process mining is included in Premium (50 MB per user) or as a $5,000/tenant/month add-on — [Power Automate pricing](https://www.microsoft.com/en-us/power-platform/products/power-automate/pricing).

**Backup and restore**
- Kestra Enterprise: "A built-in metadata backup and restore" for disaster recovery and migration, customer-controlled on self-hosted — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid), [Kestra Enterprise docs](https://kestra.io/docs/enterprise).
- Power Platform: "Extended backup" in Managed Environments. Pipelines automatically store solution backups for every deployment — [Managed environments overview](https://learn.microsoft.com/en-us/power-platform/admin/managed-environment-overview), [Power Platform pipelines](https://learn.microsoft.com/en-us/power-platform/alm/pipelines).

**SLAs and support**
- Windmill EE: "24/7 priority, 3h response, dedicated Slack channel" — [Windmill pricing](https://www.windmill.dev/pricing).
- Make Enterprise: 24/7 support with a dedicated value engineering team — [Make Enterprise](https://www.make.com/en/enterprise).
- Zapier Enterprise: Technical Account Manager, plus priority support on Team — [Zapier pricing](https://zapier.com/pricing).

**Multi-tenant, embedded and white-label**
- n8n **Embed** is a paid licence to rebrand n8n or build it into a commercial product — [n8n Embed](https://docs.n8n.io/embed/), [n8n white labelling](https://docs.n8n.io/embed/white-labelling/). n8n **OEM** embeds the canvas but keeps n8n branding — [n8n OEM](https://n8n.io/oem/). Forum posts cite about $50k/yr, which is unofficial — [n8n community](https://community.n8n.io/t/selling-n8n-workflow-for-calls/194011).
- Workato **Embedded**: a Managed Customers API (`/api/managed_users`), with Dev, Test and Prod per customer, customer managers with RBAC, and rate limits of 1,000 or 60 requests per minute — [Workato Embedded managed customers](https://docs.workato.com/oem/oem-api/managed-users.html), [Workato Embedded environments](https://docs.workato.com/en/oem/embedded-environments/provision-embedded-environments.html), [Workato customer managers](https://docs.workato.com/oem/admin-console/customer-managers.html).
- Tray.ai Embedded: solutions and solution instances, with one org per environment — [Tray Embedded](https://tray.ai/solutions/embedded), [Tray environment setup](https://tray.ai/documentation/tray-uac/development-and-testing/environment-promotion/setting-up-your-environment).
- Make OEM / white label — [Make white label](https://www.make.com/en/white-label) **[old: page metadata suggests about 9 years]**.
- Kestra Enterprise multi-tenancy: isolated tenants with separate secrets managers and storage — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid). Windmill has a "White Label" pricing toggle with no details — [Windmill pricing](https://www.windmill.dev/pricing).

### Inferences
- **Table stakes (self-hosted free):** Postgres option, pruning on by default with age and count limits, a per-instance concurrency cap, Prometheus metrics, health endpoints, and failure hooks (error workflow or webhook).
- **Table stakes (team/business paid):** a queue with workers, an insights dashboard with failure rate and time saved, and 30-day history.
- **Differentiators:** multi-main/HA, worker-group routing and autoscaling, worker UI, critical infrastructure alerts (queue length, worker down), 1-year insights, built-in backup and restore, SLAs, and embedded or multi-tenant offerings.
- n8n's "time saved" Insights, with a free summary banner, are now the reference ROI dashboard for this category, because they turn automation into a reportable business metric.

## 7. Comparison with Landflow: what it lacks, what each feature does for users, and how much it matters

### Takeaway
Landflow's credential security (AES-256-GCM, write-only secrets, per-node credential scoping) and free OTLP and Prometheus export are at or above market for a self-hosted free tier. Windmill charges for OTel and Prometheus. Landflow is below the market floor on four things every self-hosted competitor ships free: authentication, execution pruning, version history and drafts, and workflow import/export. These are the core items for the single-team phase. Most enterprise items (SSO, SCIM, RBAC, audit, SIEM, external secrets, environments, HA) are universally paid, so they can wait for the enterprise phase. Building audit events into OTLP now would make SIEM streaming almost free later.

### Cited Findings
- Landflow inventory (from the research brief): no sign-in, users, teams, roles or sharing, and the host binds to localhost. Credentials vault uses AES-256-GCM with a key from an env var or a generated file, secrets are never returned by the API, and plugins get only declared credentials. Storage is JSON files in one process with an in-process scheduler, no queue or workers, and no HA. No execution retention or pruning and no audit log. OTLP traces, metrics and logs plus Prometheus. No version history, environments, git, variables, external secrets, import/export beyond agent JSON, public-API keys, usage insights or team templates.
- Market reference points for the free tier: n8n pruning is on by default at 14 days and 10,000 executions — [n8n execution data](https://docs.n8n.io/hosting/scaling/execution-data/). n8n gives 24-hour version history to all users and JSON download of versions — [n8n workflow history](https://docs.n8n.io/workflows/history/). n8n's concurrency cap is free through an env var — [n8n concurrency control](https://docs.n8n.io/hosting/scaling/concurrency-control/). Kestra OSS has basic auth and draft revisions — [Kestra OSS vs paid](https://kestra.io/docs/oss-vs-paid), [Kestra pricing](https://kestra.io/pricing). Windmill CE has users and SSO for 10, git sync for 2, and 30-day retention, while OTel and Prometheus are EE — [Windmill pricing](https://www.windmill.dev/pricing). The n8n Insights summary banner is free — [n8n Insights](https://docs.n8n.io/insights/).
- Distributed-mode prerequisites: n8n doesn't support distributed mode on SQLite and requires shared Postgres, Redis and a shared encryption key — [n8n queue mode](https://docs.n8n.io/hosting/scaling/queue-mode/).
- Credential scoping comparator: n8n resolves external secrets only in credential fields — [n8n external secrets](https://docs.n8n.io/external-secrets/).

**Sequencing implications** (inferred from the table and evidence):
1. **Single-team phase, core:** auth (#1), pruning (#2), versions and drafts (#3), import/export (#4), API keys (#5), failure alerts (#6). Each is free in at least one direct self-hosted competitor, and #2 is an operational risk with unbounded JSON files.
2. **Cheap differentiators to do early:** git sync of the JSON workflow files (#9) and OIDC login (#16). n8n paywalls both (Business/Enterprise), so offering them free is a clear selling point for a self-hosted product. Landflow's existing free OTel/Prometheus is a similar differentiator against Windmill.
3. **Enterprise foundation work that changes architecture, so design it now even if it ships later:** a DB backend (#10) as a prerequisite for queue/HA (#26, #27), and an event model that already emits audit events through the existing OTLP pipeline (#13, #14). Also an identity model with projects and roles (#15) that credentials and variables can be scoped to, so external secrets (#19) and environments (#20) can use the same scoping, as n8n does with project-scoped vaults.
4. **Enterprise differentiators beyond n8n parity:** change approvals (#21), DLP/MCP tool policies (#22), ownership transfer (#31). These are weak or absent in n8n, Make and Zapier, and strongest only in Power Platform.

### Gaps
- Whether Landflow executes user-supplied code or third-party plugins in-process determines whether sandboxing (#25) is core now. The brief doesn't say.
- The number of users in the "single team" target isn't specified, which affects whether RBAC (#15) and edit locking (#30) are core or nice-to-have.
- I found no verified data on how often self-hosted users actually rely on free-tier version history or git, so priorities here are judgement based on vendor packaging, not usage statistics.
