# Hosted no-code automation platforms (Zapier, Make, Power Automate) vs Landflow: feature sets and gaps (state as of 2026-10-25)

## Zapier: what does it offer beyond "trigger -> actions", and what was new in 2025-2026?

### Takeaway
Zapier has grown from a linear Zap builder into a suite: Zaps (Paths, Filter, Formatter, Delay, Looping, Sub-Zaps, per-step custom error handlers, versions), Tables, Interfaces/Forms, Chatbots, Canvas, AI by Zapier, AI Guardrails and Zapier MCP. Tables, Interfaces and MCP are now bundled into Free/Pro/Team plans. The big 2026 change is **Next Gen Zaps** (announced 23 Sep 2026, early access only). They add branches that split and rejoin, nested loops with no 500-item cap, continue-on-failure, human-in-the-loop pauses, a "self-healing" monitoring agent, and authoring from MCP clients (Claude/ChatGPT/Cursor), code or a canvas. The standalone **Zapier Agents** product is being folded back into Zaps as an "AI by Zapier" step (deprecation in progress).

### Cited Findings
**Core Zap building blocks**
- Filter stops the whole Zap for runs that don't match. Paths route data down conditional branches. Path branches run one after another, left to right, so a Delay in path A holds up path B — [Zapier Help: Paths](https://help.zapier.com/hc/en-us/articles/8496288555917-Add-branching-logic-to-Zap-workflows-with-Paths)
- Sub-Zaps are reusable mini-workflows: change one once and it changes everywhere it is called. A Zapier Manager "new Zap error" trigger can call a Sub-Zap to centralise error handling — [Zapier: Sub-Zap + Zapier Manager](https://zapier.com/apps/sub-zap-by-zapier/integrations/zapier-manager/1386110/handle-new-zap-errors-in-zapier-manager-by-calling-sub-zaps-in-sub-zap-by-zapier)
- Classic Zaps have a 500-item loop cap, which Next Gen Zaps remove — [Zapier Community: Next Gen Zaps announcement](https://community.zapier.com/product-updates/the-next-generation-of-zaps-is-here-53832). Community threads report that Looping iterations run in parallel rather than in order (a frequent complaint) — [Zapier Community thread](https://community.zapier.com/how-do-i-3/how-to-force-the-iterations-of-looping-by-zapier-to-follow-a-specific-sequence-26516); [Zapier Community: looping + delay](https://community.zapier.com/how-do-i-3/looping-large-dataset-with-delay-step-52235)
- Billing: a Zapier plan update says Filter, Formatter, Paths, Delay, Looping, Sub-Zap, Digest, Zapier Manager, Storage, Tables and Interfaces steps no longer count as tasks. **Flag:** this announcement is older (pre-2025) and may have been superseded — [Zapier Help: plan improvements](https://help.zapier.com/hc/en-us/articles/22923011763853-We-re-making-some-big-improvements-to-Zapier-plans)

**Error handling, history, replay, versions**
- Custom error handling attaches per step: a Zap can have several handlers but only one per step. A run whose handler fires is marked "handled" and the Zap is not switched off. Publishing a Zap with error handling turns off autoreplay for that Zap (the account-level autoreplay setting is unchanged). Runs that include a handler can't be replayed step by step, only as a whole Zap run, and no error notification emails are sent when a handler runs — [Zapier Help: Set up custom error handling](https://help.zapier.com/hc/en-us/articles/22495436062605-Set-up-custom-error-handling); [Zapier blog: Introducing error handling](https://zapier.com/blog/zap-error-handling/); [Zapier Help: Troubleshoot errors](https://help.zapier.com/hc/en-us/articles/8496037690637-How-to-troubleshoot-errors-in-Zap-workflows)
- Zap history: a log of runs you can view and manage, including replay — [Zapier Help: View and manage your Zap history](https://help.zapier.com/hc/en-us/articles/8496291148685-View-and-manage-your-Zap-history)
- Versions: every publish creates a version. Users can view past versions, compare version outlines, create drafts from old versions and name versions as a changelog. Retention by plan: Free none, Pro 1 month, Team 6 months, Enterprise 1 year (available on paid plans since 13 Oct 2022) — [Zapier Help: Create Zap drafts and versions](https://help.zapier.com/hc/en-us/articles/9693520498445-Create-Zap-drafts-and-versions). Change history can be reviewed inside the editor — [Zapier Help: change history in editor](https://help.zapier.com/hc/en-us/articles/23975937613069-Easily-review-your-Zap-s-change-history-from-within-the-editor)

**AI building and AI features**
- Copilot: an AI chatbot in the editor's left sidebar that helps build Zaps (beta since Jan 2024, so older) — [Zapier Help: Use the editor](https://help.zapier.com/hc/en-us/articles/16722578092429-Use-the-editor-to-build-and-view-your-Zap-workflows)
- **Zapier Agents is being migrated to "AI by Zapier"** (page updated 1 Oct 2026). Each agent becomes a Zap with a native trigger plus a single AI by Zapier step, and tools, prompt and reasoning carry into that step. Chat-triggered agents have no direct equivalent yet (use a webhook trigger instead). Agent-to-agent calls become Sub-Zaps. Knowledge sources are only partly supported (Notion with caveats; HubSpot, Asana, Zendesk, Zoom and Jira planned for Q4 2026). No shutdown date has been set — [Zapier Help: Migrating from Agents to AI by Zapier](https://help.zapier.com/hc/en-us/articles/47402591569805-Migrating-from-Agents-to-AI-by-Zapier)
- AI by Zapier pricing: standard task-based pricing with Standard/Advanced/Premium model tiers. Runs pause for review at 75 tasks by default (adjustable up to 500). Full-Zap tests consume tasks. Per-tool approvals exist for sensitive actions. Users can bring their own API key to lower the task multiplier, but admin-level Bring Your Own Model is not available yet — [same article](https://help.zapier.com/hc/en-us/articles/47402591569805-Migrating-from-Agents-to-AI-by-Zapier)
- **AI Guardrails by Zapier** (early 2026): a built-in app that detects 30+ PII types (block or redact), flags prompt injection and jailbreak attempts, screens toxicity and scores sentiment. Results are structured so they can drive Paths and Filters — [Zapier blog: February 2026 product updates](https://zapier.com/blog/february-2026-product-updates/) (post undated on page; the URL slug says Feb 2026)

**Tables, Interfaces/Forms, Chatbots, Canvas, MCP**
- Tables, Interfaces and **Zapier MCP** are included in Free, Pro and Team plans with no add-on (page updated 21 Aug 2026, filed under "Product updates: September 2025") — [Zapier Help: Tables, Interfaces, and MCP now included](https://help.zapier.com/hc/en-us/articles/39645433045773-Zapier-plan-updates-Tables-Interfaces-and-MCP-now-included)
- Forms: linked-record fields become live dropdowns sourced from a Table, and Table formula fields show calculated values before submission — [Zapier blog: Feb 2026 updates](https://zapier.com/blog/february-2026-product-updates/)
- Canvas: a visual process map. In 2026 folders gained a Documentation tab (Markdown notes, a pinned Canvas, and one-click generation of an editable Canvas mapping the Zaps, Tables, Interfaces, Chatbots and Agents in the folder) — [Zapier blog: Feb 2026 updates](https://zapier.com/blog/february-2026-product-updates/)
- Favorites for folders, Zaps, Tables, Forms, Chatbots and Canvases. An org-wide Chatbots kill switch (via Support, not self-serve). A billing audit log for Team/Enterprise admins. Agent templates in the Templates hub. A Lead Router app (queues, rep assignment, rep-availability actions) — [Zapier blog: Feb 2026 updates](https://zapier.com/blog/february-2026-product-updates/)

**Next Gen Zaps (announced at ZapConnect, 23 Sep 2026; early access)**
- Can be built from MCP-enabled AI tools (Claude, ChatGPT, Cursor) and deployed to Zapier, or built in Zapier with natural language, code or a visual canvas. Adds: whole-list processing with no 500-item cap, nested loops rolled up into summaries, branches that split and rejoin, failure in one step that doesn't stop the run, pauses for a human reply or scheduled follow-up that resume automatically, and "Agentic Management" (a monitoring agent diagnoses failures and applies or suggests fixes). Early access is on Pro/Team/Enterprise; on Team plans an owner or admin must request it — [Zapier Community: The next generation of Zaps is here](https://community.zapier.com/product-updates/the-next-generation-of-zaps-is-here-53832)
- Next Gen Zaps run through Zapier MCP and keep running on their trigger or schedule without a chat window open. A fix applied by Agentic Management is published as a new version visible in version history. Next Gen Zaps are managed in a "Workflow Manager" — [Zapier Help: Get started with Next Gen Zaps](https://help.zapier.com/hc/en-us/articles/48391476448141-Get-started-with-Next-Gen-Zaps); [Zapier Community announcement](https://community.zapier.com/product-updates/the-next-generation-of-zaps-is-here-53832)

**Other 2026 items (secondary sources, not verified on a primary page)**
- "Guided templates" (around Apr-May 2026) turn finished Zaps into step-by-step setup flows for teammates, with some fields locked. A Zap can only be turned on if its owner has access to every connection it uses. Code by Zapier runtime was raised to 10 minutes (Apr 2026) — [Releasebot: Zapier release notes](https://releasebot.io/updates/zapier); [Zapier Community product updates index](https://community.zapier.com/product-updates)
- The developer platform now checks for breaking changes when a version is promoted and guides integration authors to the correct semver — [Zapier Platform News 2026](https://docs.zapier.com/integrations/news/2026)

### Inferences
- Zapier's direction is "AI agent = a step inside a deterministic workflow", not a separate agent product. That suggests Landflow's split between standalone Agents and the AI Agent node is defensible, but users will expect the two to share triggers, history and billing.
- Next Gen Zaps is Zapier catching up to n8n/Make-style graph semantics (branch-and-rejoin, nested loops, continue-on-error). Landflow's n8n data model already covers most of this, so the competitive gap is now in the surrounding features: versioning, error routes, human-in-the-loop, MCP authoring and self-healing.
- Bundling Tables, Interfaces and MCP into every plan signals that data storage, forms and MCP are now table stakes, not upsells.

### Gaps
- Could not find Zapier Interfaces page/limits, Chatbots capabilities, Transfer (bulk send historical data) or bulk-replay specifics on a primary page in this pass. Those features exist, but no 2026 details were verified.
- Team/Enterprise admin (SSO, SCIM, shared connections, roles) was not verified beyond the billing audit log and the AI/Chatbots org toggles.
- GA status of Next Gen Zaps as of 25 Oct 2026 is unknown (early access only per the sources found).
- Delay limits (about 4 weeks max, held tasks expiring after a month) appear only in community threads — [Zapier Community](https://community.zapier.com/featured-articles-65/how-to-have-a-zap-delay-during-non-business-hours-3553). Treat as unverified.

## Make (formerly Integromat): what does it offer beyond "trigger -> actions", and what was new in 2025-2026?

### Takeaway
Make is the most graph-native of the three. It has routers, iterators and aggregators, filters, If-Else/Merge (2026), module-level error handlers plus "incomplete executions" (resumable failed runs), data stores with data structures, webhooks/mailhooks, subscenarios and scenario inputs (scenarios as callable functions/APIs), Make Code (JS/Python), and an MCP server and client. It shipped very heavily in 2026: Make AI Agents app (Feb), Make Grid updates, Make CLI and Make Skills for AI coding tools, Maia as an in-builder AI co-worker (Aug), version control (Oct), custom roles and private spaces, subfolders and labels, scenario trash and recovery, AI error explanations, and signed event subscriptions.

### Cited Findings
**Core scenario model**
- Error handlers are modules attached to a specific module, and run only when that module errors. "Incomplete executions" instead affect the whole scenario: the failed run is stored with its data and blueprint for later resumption — [Make Academy: Error handlers](https://academy-content.make.com/courses/make-intermediate-errors/04-error-handlers/); [Make Help: Overview of error handling](https://help.make.com/Overview-of-error-handling)
- Handler semantics: Break stores the failing bundle as an incomplete execution (with configurable retry attempts and interval) while other bundles keep going. Commit stops and keeps processed changes. Rollback stops and reverts changes. Resume substitutes a predefined output and continues. Ignore drops the error and continues. A Throw module raises errors deliberately — [Make Help: Error handlers](https://help.make.com/error-handlers); [Make Help: Commit](https://help.make.com/commit-error-handler); [Make Help: Throw](https://help.make.com/throw)
- **Naming change (June 2026):** Make's release log lists "renamed error handlers" on 6 Jun 2026 — [Make Help: 2026 releases](https://help.make.com/2026). The current help-center quick reference reportedly uses **Skip** and **Retry** where older docs say Ignore and Break, while the Academy still uses the old names — [Make Help: Error handlers](https://help.make.com/error-handlers); [Make Academy](https://academy-content.make.com/courses/make-intermediate-errors/04-error-handlers/). Sources conflict, so verify before copying the names.
- Hooks is the umbrella term for webhooks and mailhooks. A custom mailhook gives an email address that triggers the scenario instantly (no polling) — [Make Developers: Hooks API](https://developers.make.com/api-documentation/api-reference/hooks); [Make Help: Webhooks](https://help.make.com/webhooks)
- Data structures define record shapes for data stores and can validate incoming webhook payloads. Without one, webhook data passes through unvalidated — [Make Help: Webhooks](https://help.make.com/webhooks)
- Scenario inputs are now available to all users (previously Pro+). The run API accepts inputs in a `data` object, and scheduling is set via the API's `scheduling` field — [Make Help: Scenario inputs for all users](https://help.make.com/scenario-inputs-now-available-for-all-users); [Make Developers: Scenarios API](https://developers.make.com/api-documentation/api-reference/scenarios)

**Waves '25 announcements (Oct 2025; status then: "now", "waitlist" or "early 2026")**
- Subscenarios: turn any scenario into a reusable function or API callable by other workflows or AI agents (all plans). Scenario Run Replay: re-run scenarios with historical trigger data (all plans). If-Else and Merge (early 2026). Scenario sharing via one secure link. Maia (conversational AI builder; waitlist then). Next-gen Make AI Agents built in the scenario builder, where you watch reasoning and actions live and can add files and conversation history (waitlist then). Agent library. Module Tools (any module becomes an agent tool). Make AI Provider (LLMs without your own API key). Make Code (JS/Python sandbox on paid plans; third-party libraries, higher limits and a 300 s runtime on Enterprise, 30 s otherwise). Make Grid (real-time map of the automation landscape with cost/consumption tracking, issue highlighting and shareable snapshots). **MCP Server** (exposes scenarios as tools to Claude/GPT/Cursor) and **MCP Client** (scenarios call external MCP tools). Scenario rate limits. Authenticated webhooks. Credits per team (Enterprise) — [Make blog: Waves '25 product releases](https://www.make.com/blog/waves-make-product-releases-2025)

### Inferences
- Make's 2026 work is mostly governance and maintainability rather than new logic: version control, trash/recovery, undo/redo, folders/labels, global search, custom roles, private spaces, audit-log MCP tools and Module Migrator. That matches the top G2 complaint that large scenarios become hard to track (see the sentiment section).
- Make treats "scenario as a function" (subscenarios + scenario inputs + MCP server) as a single concept that serves workflow reuse, an API surface and agent tools at once. That is a cheap, high-leverage pattern for Landflow to copy.
- Make Skills, the CLI and the Claude/ChatGPT connectors show Make positioning itself as the execution back end for external coding/chat agents, not only a UI.

- The Teams/Organizations model was not detailed beyond custom roles, private spaces and credits per team.

## Microsoft Power Automate: what does it offer beyond "trigger -> actions", and what was new in 2025-2026?

### Takeaway
Power Automate is three products in one: cloud flows (connector-based, Copilot-assisted, AI Builder document processing, approvals, mobile app), desktop flows (Windows RPA with work queues and machine management) and process/task mining. It is wrapped in enterprise governance (environments, managed environments, DLP connector policies, Process licences, admin-centre reporting). 2026 investment went into desktop flows (version control and compare, test suites, PGP, local AI models, Python, video logs), object-centric process mining with an MCP server, Copilot Studio-powered actions in cloud flows, and Copilot Studio "agent flows/workflows" that can call MCP tools. Microsoft archived its release-plan pages in Oct 2026 in favour of a unified roadmap, and no official 2026 wave 2 Power Automate plan page could be retrieved.

### Cited Findings
**Product scope (2026 wave 1 overview, Apr-Sep 2026)**
- Cloud flows: Copilot-assisted creation across Teams, SharePoint, OneDrive and Dynamics 365. Can be invoked from Power Apps, Power BI data alerts and Copilot Studio. Intelligent document processing via AI Builder. Mobile apps for notifications, **approvals**, and invoking and monitoring runs — [MS Learn: Power Automate 2026 wave 1 overview](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/)
- 2026 wave 1 focus: self-healing desktop automations; **Copilot Studio-powered actions in cloud flows**; calling desktop flows directly from Copilot Studio; desktop flowchart view, real-time collaboration, version control, centralised credential management and machine templates; cloud-flow capacity notifications, Process licence sharing via flow groups and **self-service restore**; object-centric process mining with a **Model Context Protocol (MCP) server**, Copilot Studio agents and a Power Platform connector; consolidated licensing and usage reporting plus expanded inventory (flow dependencies and connections) in the admin centre — [MS Learn: 2026 wave 1 overview](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/)
- **Status flag:** both 2026 wave 1 pages say "As of October 2026, this content is archived and no longer maintained" and point to a unified roadmap (aka.ms/AIatWorkRoadmap) — [MS Learn: 2026 wave 1 planned features](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/planned-features)

**Copilot Studio agent flows / workflows and MCP**

**Governance, ALM, licensing, approvals**
- DLP ("data") policies sort connectors into Business, Non-business and Blocked groups, and one resource can't mix Business and Non-business connectors. Some Microsoft standard connectors can't be blocked. Microsoft recommends tenant-level policies, with environment-level policies for exceptions or custom connectors — [MS Learn: Manage data policies](https://learn.microsoft.com/en-us/power-platform/admin/create-dlp-policy); [MS Learn: DLP strategy](https://learn.microsoft.com/en-us/power-platform/guidance/adoption/dlp-strategy)
- Licensing: a Premium user licence gives premium and custom connectors, managed environments and Dataverse storage. A Process licence attached to a flow gives it higher action limits and premium/custom connectors regardless of user licence — [MS Learn: Types of Power Automate licenses](https://learn.microsoft.com/en-us/power-platform/admin/power-automate-licensing/types)
- Environments strategy (dev/test/prod separation, managed environments) — [MS Learn: Environment strategy](https://learn.microsoft.com/en-us/power-platform/guidance/adoption/environment-strategy)
- Approvals: the Approvals connector plus a "Business approvals kit" (Dataverse-backed multi-stage approvals that need DLP grouping of the Approvals, Dataverse and Office 365 Users connectors) — [MS Learn: Business approvals kit setup](https://learn.microsoft.com/en-us/power-automate/guidance/business-approvals-templates/setup)

### Inferences
- Power Automate's distinctive value for its buyers is governance (DLP connector classes, environments, licence capacity, inventory) and Microsoft-estate reach (RPA for legacy Windows apps, M365 approvals in Teams/Outlook/mobile). Landflow should not chase RPA or process mining. DLP-like "allowed nodes per workspace" and environment promotion are the transferable ideas.
- Microsoft is shifting new "AI workflow" investment from Power Automate cloud flows into Copilot Studio workflows/agent flows. Expect Power Automate cloud-flow innovation to stay incremental.

## What do users most praise or miss on each platform?

### Takeaway
Zapier is praised for ease of use and catalogue breadth, and criticised for cost at scale and weak branching/looping (partly answered by Next Gen Zaps). Make is praised for its visual builder, power and price, and criticised for a steep learning curve (error handlers, iterators/aggregators), unclear error messages, weak docs/support and hard-to-track large scenarios. Power Automate is praised inside Microsoft 365 shops and regulated industries, and criticised for an unintuitive UI and premium-connector licensing cost. Direct Reddit evidence could not be gathered (domain blocked to the crawler).

### Cited Findings

## How does Landflow compare, which features does it lack, what does each do for users, and how much does it matter?

### Takeaway
Landflow's editor and engine (canvas, n8n item model, expressions, partial execution, pin data, a breakpoint debugger, an AI builder with diffs and undo, local-LLM support, OTel) are at or above parity with the hosted leaders. Its gaps are almost all in the "platform around the workflow". In priority order: error routes/error workflows, sub-workflows, version history, OAuth "Connect" plus instant app webhooks, richer scheduling, and multi-user/RBAC are **core**. Data tables, forms, MCP server/client, human-in-the-loop in workflows, binary files, folders/notes, templates and replay ergonomics are **important**. Grid/Canvas-style maps, AI guardrails, self-healing, RPA and process mining are **nice-to-have or out of scope**.

### Cited Findings
(The evidence for each competitor feature is cited in the table below. Landflow's capabilities come from the inventory in the assignment brief.)
- All three competitors ship AI builders: Zapier Copilot ([Zapier Help](https://help.zapier.com/hc/en-us/articles/16722578092429-Use-the-editor-to-build-and-view-your-Zap-workflows)), Make's Maia in the Scenario Builder since 12 Aug 2026 ([Make Help 2026](https://help.make.com/2026)), and Copilot-assisted cloud flow creation ([MS Learn](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/)). Landflow's AI flow builder plus diff-proposing builder chat is therefore table stakes, not a differentiator. Local Ollama is still distinctive: Power Automate's "connect to local AI models" is desktop-flows-only and in preview ([MS Learn](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/planned-features)), and Zapier lacks admin-level BYO model ([Zapier Help](https://help.zapier.com/hc/en-us/articles/47402591569805-Migrating-from-Agents-to-AI-by-Zapier)).
- Runtime debugging is still being added by competitors: Power Automate "debug into condition actions at runtime" (Dec 2025) and "debug flows using variable default values" (Jun 2026) ([MS Learn 2025w2](https://learn.microsoft.com/en-us/power-platform/release-plan/2025wave2/power-automate/planned-features); [MS Learn 2026w1](https://learn.microsoft.com/en-us/power-platform/release-plan/2026wave1/power-automate/planned-features)), and Make's AI error explanations and raw-data view (Jul and May 2026) ([Make Help 2026](https://help.make.com/2026)). Landflow's breakpoint debugger is ahead of these.
- Graph semantics that Zapier only now offers in early-access Next Gen Zaps (branch-and-rejoin, nested loops, continue-on-error, no 500-item cap) — [Zapier Community](https://community.zapier.com/product-updates/the-next-generation-of-zaps-is-here-53832) — are already native to Landflow's n8n-style model (Merge, Split Out, Aggregate, onError continue).

**Where Landflow is at parity or ahead (keep and market)**
- Item-based graph engine with Merge/Split Out/Aggregate, continue-on-error and retries. Zapier only gets equivalent semantics in Next Gen Zaps (early access).
- Breakpoint debugger, pin data and partial execution go beyond the runtime-debug features competitors added in 2025-2026.
- OpenTelemetry tracing: no equivalent was found for any of the three (an absence, not confirmed by a source).
- Local-LLM (Ollama) builder and agents, which suits privacy-sensitive users. Competitors rely on hosted models or BYO keys.
- Plugins in any language vs Make's custom-app definitions and Zapier's developer platform. This is an advantage for developers, but the marketplace-size gap (~20 integrations vs thousands) remains the biggest strategic weakness. It is not a "feature" to build but drives the value of #10 (MCP client) and HTTP Request.

**Suggested build order (inference)**
1. Error output branch + error workflow, sub-workflows with inputs/outputs, version history with diff/restore (these three reinforce each other).
2. OAuth Connect + instant webhook triggers + cron schedules + binary data.
3. Users/roles plus folders/tags/search.
4. MCP server (built on sub-workflows) and MCP client in the AI Agent node; human-in-the-loop Wait/Approval node.
5. Data tables, a Form trigger, variables/environments, cost guards.
6. Nice-to-haves (sticky notes, Grid-style map, guardrails, self-healing on top of versioning).
